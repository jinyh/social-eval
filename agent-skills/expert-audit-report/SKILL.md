# 单篇评审 · 专家审计最终报告 改写指南

把一篇论文的多模型 AI 评审原始数据，改写成文科教授能直接审读的审计最终报告。原始数据是机器视角（JSON 字段路径、英文代码枚举、逐模型铺陈），专家要的是中文学术表述、共性/分歧一目了然、每处分歧附"该盯什么"的提示。本 skill 把这套改写规则固化下来，保证每篇报告一致。

黄金标准 exemplar：`docs/presentations/P8-朱军单篇案例-专家审计最终报告.md`（paper-1322）。下文每条规则都能在该文件找到对应。**改写前先扫一眼 exemplar 的结构与语气再动笔**——exemplar 是结构范式的唯一参照。

## 什么时候使用

- 用户给一个 paper ID（如 1322、paper-507），要产出给专家/文科教授审计看的最终报告。
- 用户说"把这篇的评审结果整理给专家看""出一份 paper-X 的单篇审计报告""生成专家审阅报告"。
- 已有原始审计报告（`gen_paper1322_audit_report.py` 风格的机器向报告）要改写为专家向。

不触发：用户只是查某篇分数、看某维度评语、跑评审脚本——这些直接读数据或跑脚本即可。

## 输入：5 个数据源（路径按 pid 参数化）

| # | 数据 | 路径 | 取法与字段 |
|---|---|---|---|
| 1 | 元数据 | `results/merged-metadata.csv` | `编号`={pid} 行，取 题目/作者/作者机构/期刊/年份/卷/期/页数/主题词 |
| 2 | 六维评审 | `results/fullevaluation/round2/paper-{pid}.json` | `dimensions[*]`（每维 `round1_scores`/`round2_scores`/`round1_mean`/`round2_mean`/`round1_std`/`round2_std`/`raw_outputs[model]`）、`overall.*` |
| 3 | 五轴评估 | `results/fullpaper-position-assessment-stage0/merged/paper-{pid}.json` | `final.*`（`axis_scores`/`total_score`/`strength`/`agreement_level`/`research_route`）、`round2.round2_policy`、`round{1,2}.models[m].research_route`、各模型 `axis_scores[axis].{score,rationale,evidence_quotes}`。**此为 1920 篇全量五轴权威源**（restic 备份恢复，2026-07-12）；个别论文缺失时降级省略 §3 |
| 4 | 候选池 | `results/e2-pool/ranking_v5_pool.json` | 按 pid 查 `papers` 条目，取 `rank`（**E2 候选池排名唯一来源**）、`weighted_score`、`weighted_std`、`dimensions[*]`（维度字段是英文 code，**用同条目的 `name_zh` 字段映射中文名**） |
| 5 | CCB 总分 | `results/report_paper_master.csv` | pid 行，取 `weighted_score`（**CCB 总分唯一来源，core_ceiling_bonus=base+bonus+ceiling**）；该行还有 top101_rank/top50_rank 等，**不要用它们作 E2 排名** |

**降级原则**（用户要求支持任意论文 ID）：
- 六维文件缺失 → 报错退出（报告基石，不能少）。
- 五轴文件缺失 → 省略 §3 五轴、§2.1 五轴指标；§0 注明"本篇未做五轴位置归属度评估"。
- pid 不在候选池 → 省略 §5；§0 注明"本篇未入 E2-Top102 候选池"。
- 元数据/加权分缺失 → 该字段留空或省略，不报错。

Paper ID 权威来源：始终以 `merged-metadata.csv` 的 `编号` 字段为准，不要从中间文件或缓存构建映射（详见 CLAUDE.md「Paper ID 映射」警告）。

## 输出结构（务必按此层级，含表格优先；章节标题统一用 `## §N.` / `### §N.M` 格式带 § 前缀）

```
§0 阅读说明（R7 五条 + R5 术语）
§1 论文元数据（表）
§2 顶层结论（开头一句定性总评，呼应 exemplar 风格）
   §2.1 五轴位置归属度指标（表）       ← 五轴在前
   §2.2 六维内容质量指标（表）
   [§2 总览审计提示]                    ← 见 R2 末段
§3 五轴位置归属度评估
   §3.1 五轴汇总（表：轴|最终分|模型A|模型B，含总分行 + 强度/一致性/争议轴/是否复审）
   §3.2 R2 触发与分歧（R2 模式/触发原因/轴分分歧 + 研究路径表 + 各模型路径理由）
   §3.3 五轴综合：共性结论 + 分歧点表 + 审计提示   ← 五轴只用一个综合段
   §3.4 逐轴×逐模型证据（每轴：##### 轴名·模型，分数/判断理由/论文原文引文；引文取 R2 层 round2.models，不回退 R1）
§4 六维内容质量评审
   §4.1 评分汇总（表：维度|权重|各模型R1/R2|R1均值|R2均值|R1 std|R2 std|收敛改善；权重列写数值 0.30/0.20/0.15/0.20/0.10/0.05，不用「封顶/加分」角色标签替代数值）
   §4.2 收敛说明（一句：六维全部收敛，R2 平均标准差 X，属高度收敛样本）
   §4.3 逐维度×逐模型证据（每维度：共性+分歧表+审计提示，再接各模型 ##### 子节）
§5 E2-Top102 候选池聚合（只留主表）
```

输出到 `docs/presentations/`，文件名 `P{n}-{作者关键词}-专家审计最终报告.md`，或按用户指定。

**表格优先**：§2.1/§2.2/§3.1/§3.2/§4.1 用 Markdown 表格，不要用项目符号列表替代——表格让专家横向对照模型/维度。

**降级时章节顺延**：五轴缺失则去掉 §3（五轴）与 §2.1（五轴指标），六维评审顺延为 §3、§2 只剩六维指标小节（标 §2.1），**子节号同步顺延**（§4.1→§3.1、§4.2→§3.2、§4.3→§3.3）；候选池缺失则直接去掉 §5，不留空号、不补占位。§0 第 3 条注明降级原因（"未做五轴位置归属度评估""未入 E2-Top102 候选池"）。

## 改写规则（核心，7 条）

### R1 顺序：五轴在前、六维在后

§2 拆 §2.1 五轴指标（先）/ §2.2 六维指标（后）。§3 整章在 §4 之前。这是与原始机器报告（六维在前）的关键差异。

### R2 共性/分歧/审计提示——五轴与六维结构不同（关键）

**六维（§4.3 每维度各一组）**：每个维度下依次写 共性结论 → 分歧点表 → 审计提示 → 逐模型证据。

**五轴（§3.3 只写一个综合段）**：五轴整体只写**一组** 共性结论 + 分歧点表 + 审计提示（放在 §3.3），不要在每个轴下重复。逐轴证据（§3.4）只放分数/判断理由/原文引文，不再各写共性/分歧。原因：五轴两模型通常轴分一致，分歧多在研究路径层面，按轴切会全是"无分歧"，浪费篇幅。

**共性结论**：多数模型一致认可的判断，2-4 条。
- **不点名具体模型**：保留共识广度表述（"四模型一致""三模型评 excellent 档、一模型评 good 上限"）——这种广度不算归属，允许。
- **真正要避免的**：把具体证据事实归属于某模型，如"kimi 新发现证据：…""qwen 反驳证据：…"。改为中性陈述（"论文脚注〔16〕引用 Wiedemann 1966…""管理类因素衡量 279 次 vs 经济类 134 次"），不挂模型名。

**分歧点表**：列 = `分歧 | 立场与理由 | 论文证据 | 是否收敛`。
- **保留模型立场归属**：分歧本质是"谁持何立场"，必须标"`kimi-k2.6` 坚持 good 档…""`glm-5.1`/`qwen3.6-plus` 下调…"。
- 标注 R2 收敛情况（完全收敛/部分收敛/未收敛）及收敛后是否仍影响档位。
- 只收实质性学术分歧（真实判断差异、价值取向），不收模型随机波动。
- 五轴若无轴级分歧、仅路径分歧，则分歧表写那条路径分歧即可。

**审计提示**：分歧表后引用块 `> 审计提示：…`，1-2 句，三要素：
1. 分歧性质（真实学术判断 / 价值取向差异 / 计数细枝 / 模型波动）
2. 是否影响档位或总分
3. 专家可关注/定夺什么

**§2 顶层结论末也加一条总览审计提示**：指明本篇整体收敛情况 + 需专家定夺的分歧集中于哪几处、性质如何，引导直奔 §4.3 对应维度。这条不计入"每维度/轴"的提示，是单独的顶层路标。

### R3 逐模型证据：结构化分字段（不是散文）

每个维度/轴下，**每个参评模型一个 `##### 维度名 · 模型名` 子标题**，其下按字段分段（不要压成一段散文）：

```
##### 研究创新性 · `deepseek-v4-pro`

- R1 92 → R2 **92**（excellent 档）
- **核心判断**：…
- **改分理由**：…
- **采纳的其他模型意见**：
  1. …
- **拒绝的其他模型意见**：
  1. …
- **新发现证据**：
  1. …（无则写"（无）"）
```

模型名称**不匿名**（deepseek-v4-pro/glm-5.1/kimi-k2.6/qwen3.6-plus）。

**元数据行**：
- 六维：`- R1 {a} → R2 **{b}**（{excellent|good} 档）`——去 unchanged/up/down/幅度/置信度，保留档位（去反引号）。
- 五轴：`- R1 {a} → R2 **{b}**`——五轴是 0-2 分制、**无 excellent/good 档位**，不要硬套档位。

**字段子集按评审类型**：
- 六维：5 字段全要——核心判断/改分理由/采纳/拒绝/新发现证据（内容从 `raw_outputs[model]` 的 `revised_core_judgment`/`revision_rationale`/`accepted_points`/`rejected_points`/`new_evidence_found` 原样取，不缩写）。
- 五轴：3 字段——分数/判断理由/论文原文引文（五轴原始数据本就只有 `score`/`rationale`/`evidence_quotes` 三字段，无采纳/拒绝/新发现证据，不要硬凑）。

**截断引文**：原始数据里引文常以"…的""…经济从属性"等截断结尾（模型从全文抽取所致），原样保留并带省略号，不要回退 R1、不要人工补全——它是模型输出的真实样态。

### R4 文科教授向清理

- **去文件路径/字段路径**：删 JSON 字段路径（`overall.round2_avg_std`、`final.total_score`）、csv/yaml 文件路径、表格「来源」列、`（report_paper_master.csv）` 括注。
- **代码枚举译中文**：`strong`→强、`high`→高、`light`→轻度、`False`→否、`[]`→无；研究路径枚举 `china_practice_governance`→中国实践治理、`chinese_doctrinal`→中国教义学、`comparative_localization`→比较法本土化；触发原因 `route_primary_disagreement`→研究路径主路径判定分歧、`route_or_node_arbitration`→路径或节点仲裁。
- **去标题代码键**：维度/轴标题去英文 code（`problem_originality`、`object_belonging` 等），只留中文名+权重；`final 分`→最终分；`（evidence_quotes）` 标签→论文原文引文；§3.1 标题去「（final）」。
- 五轴汇总表的 `分值范围 [2,2]` 列冗余，删。

### R5 E1/E2/五轴 术语前置

§0 阅读说明必须解释这几套术语：
- **交叉评审机制（R1/R2）**：R1 各模型独立评；R2 看对方意见后重评。报告取 R2 收敛分。
- **评价阶段（E1/E2）**：E1 = 全量六维评审（全库 1920 篇，§4 详评）；因成绩靠前入选 Top102 候选池，进入 E2 二次评审（§5）；五轴位置归属度评估（§3）独立于六维，评定在自主知识体系中的位置结构。
- §2.1 候选池排名标「E2 候选池排名」，值取 `ranking_v5_pool.json` 的 `rank` 字段（不用 report_paper_master 的 top101_rank/top50_rank）。

### R6 删冗余（注意：编号指原始机器报告，不是本报告）

- 删五轴各轴末尾的 `_final 层轴级聚合引文_` 块。**识别方法**：五轴 merged 文件里 `final.axis_scores[*].evidence_quotes` 是聚合引文数组（多模型引文去重合并），删；各模型 R2 层 `round2.models[m].axis_scores[axis].evidence_quotes` 才是模型原始引文，保留。
- 删数据溯源表（原始报告 §7）与口径与边界（原始报告 §6）里的字段路径实现细节。关键 caveat（双口径、证据为 AI 生成）放进 §0。
- 删**原始机器报告的全局收敛表**（原始报告里那张 `字段|值` 列 `round1_avg_std` 等的表，与 §2.2 重复）→ 本报告 §4.2 只留一句收敛说明。注意"全局收敛表"是原始报告的概念，不要与本报告 §4.2 编号混淆。
- **§5 候选池只留主表**（E2 候选池排名/CCB 总分（E1+E2 聚合，core_ceiling_bonus）/加权标准差/两轮聚合 E1+E2）。**删** §5.1 八模型 pooled 六维表、§5.2 E1/E2 逐模型原始分表——这两张表对文科教授过技术，不要因"有信息"而保留。主表只含这 4 行，**不要加** Top50 排名、入池依据（coverage_minimum）、学科分类等附加行——那些是内部字段，对专家无意义。行名用"CCB 总分"（E1+E2 聚合分，非纯 E1 阶段分，避免误导）。
- 文末不附「由 scripts/gen_*.py 生成」溯源行。

### R7 §0 阅读说明必备 5 条

1. 模型参评范围（六维 4 模型 / 五轴 2 模型，列名）
2. 交叉评审机制（R1/R2）
3. 评价阶段（E1/E2）
4. 证据来源（核心判断/改分理由/原文引文均为 AI 模型输出，原文引文来自模型从全文抽取）
5. 双口径提示：CCB 总分（报告统一口径，`report_paper_master.weighted_score`，core_ceiling_bonus=base+bonus+ceiling，核心四维形成基础分+前瞻有条件弱加分+共识封顶）≠ R2 总分均值（四模型 R2 直接平均，六维简单均值），报告统一用 CCB 总分。**报告正文不写 csv/json 字段路径**（如 `report_paper_master.csv:weighted_score`），那些只是你定位数据用的内部信息。

降级时在 §0 相应条目注明缺失项。

## 执行步骤

1. 确认 pid（从 `merged-metadata.csv` 的 `编号` 核验）。
2. 读 5 个数据源；按降级原则处理缺失。
3. 按「输出结构」层级组装，表格优先。
4. §3 五轴：§3.1 汇总表 → §3.2 R2 触发与路径分歧 → §3.3 **一个**综合段（共性+分歧+审计提示）→ §3.4 逐轴逐模型证据（只分数/理由/引文）。
5. §4 六维：§4.1 评分汇总表 → §4.2 一句收敛说明 → §4.3 每维度各写 共性+分歧表+审计提示，再接各模型 `#####` 子节（R3 结构化分字段）。
6. §2 末加总览审计提示。
7. 全文做 R4 文科向清理（去路径、译枚举、去代码键）。
8. §0 补齐 R7 五条 + R5 术语解释。
9. §5 只留主表（R6 严格执行，不扩表）。
10. 输出到 `docs/presentations/`，文件名 `P{n}-{作者}-专家审计最终报告.md` 或按用户指定。
