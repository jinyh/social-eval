# Prompt 长度优化思路

> 日期：2026-05-20
> 版本：v1.1
> 状态：实验设计中

## 背景

v2.50.x 系列迭代中反复出现一个核心问题：**分析框架/结论维度的扣分指令未生效**。无论将扣分规则放在开头、中间还是锚定表中，AI 仍按既有评分标准给分，未能有效执行负面模式检测。

### 数据证据

| 样本 | 维度 | 预期得分 | v2.50.2 实际 | v2.53 实际 | v2.54 实际 |
|------|------|----------|-------------|-----------|-----------|
| 杨清望 | conclusion_consensus | < 60 | 92 | - | - |
| 崔聪聪 | analytical_framework | < 60 | 86 | - | - |
| 包晓丽 | analytical_framework | < 70 | 88 | - | - |
| 邵莉莉 | analytical_framework | < 65 | 64 ✓ | 90 ✗ | 85 ✗ |

- v2.50.2：10 个负样本中，8/10 在 analytical_framework 得分 84-90，9/10 在 conclusion_consensus 得分 86-94
- v2.53：模型输出明确写"前置负面检查扣 0 分"——规则存在但完全没触发
- v2.54：修复覆盖 bug 后仅下降 5 分，仍远高于预期

### 归因分析

数据证明了"扣分规则没生效"，但根本原因有两种可能解释：

1. **注意力稀释假设**：论文全文占 prompt 的 90%+，扣分指令被海量文本稀释
2. **规则模糊假设**：扣分条件定义不够具体，AI 无法判断是否触发（v2.51 失败支持此解释）

两者可能同时存在。实验设计需要能区分这两个因素。

## 当前 Prompt 结构分析

### 单次 LLM 调用的组成

| 部分 | 长度 | 占比 |
|------|------|------|
| 维度 prompt 模板 | ~400-600 字符 | ~1-2% |
| 论文全文 | 5,000-50,000+ 字符 | ~90-95% |
| 参考文献列表 | 1,000-5,000 字符 | ~5-8% |

### 完整评价流程（8 次 LLM 调用）

1. 预检（precheck）：~1,200 字符指令 + 全文 + 参考文献
2. 6 个维度评分：每次 ~400-600 字符指令 + 全文 + 参考文献
3. 自主知识信号校验：~800 字符指令 + 全文 + 参考文献

**每次调用都重复发送完整论文内容。**

### 关键发现

- **Prompt 模板本身不长**：每个维度指令仅 400-600 字符，对 LLM 来说在舒适区内
- **论文内容才是主体**：占单次输入的 90%+
- **注意力稀释是真实问题**：论文越长，LLM 对指令中细微要求（如扣分规则）的遵从度越低
- **无 token 计数逻辑**：代码中未实现发送前的长度校验

## 优化方向

### A. 分段输入（Chunked Input）

**思路**：不发全文，只发与当前维度相关的论文段落。

**实现**：
- 先做一次"段落-维度映射"（让 LLM 或规则标注哪些段落与哪个维度相关）
- 每个维度评分时只发送相关段落

**优势**：大幅缩短单次输入，指令遵从度提升
**风险**：段落切割可能丢失跨段落的论证逻辑；映射本身需要额外调用

### B. 两阶段评分（Extract-then-Score）

**思路**：
- Stage 1：给定维度 + 全文 → 提取关键证据片段（不评分）
- Stage 2：给定维度 + 证据片段 + 评分规则 → 评分

**优势**：
- Stage 2 的输入很短，扣分规则不会被淹没
- 证据提取过程本身可审计

**风险**：调用次数翻倍（12 次 → 可能 12-18 次）；Stage 1 提取不全会影响 Stage 2

### C. 结构化摘要前置（Summary-first）

**思路**：
- 先让 LLM 生成论文的结构化摘要（问题、方法、框架、结论、创新点）
- 后续维度评分基于摘要而非全文

**优势**：摘要长度可控（如限制 2000 字），后续评分 prompt 短且聚焦
**风险**：摘要可能丢失关键细节（尤其是负面信号）；摘要质量依赖第一次调用

### D. 指令位置优化（Instruction Placement）

**思路**：利用 LLM 的 recency bias，把关键扣分规则放在论文内容之后。

**当前结构**：`[指令] + [论文] + [参考文献]`
**优化结构**：`[基础指令] + [论文] + [参考文献] + [关键扣分规则/最终提醒]`

**优势**：改动最小，无需架构变更
**风险**：效果有限，不能根本解决注意力稀释问题

### E. 强制 CoT 锚定（Evidence-first CoT）

**思路**：要求 LLM 在给分前必须先引用原文证据，再判断是否触发扣分条件。

**实现**：在 output_template 中强制要求：
1. 先列出与该维度相关的原文关键段落
2. 逐条检查扣分条件是否满足（引用原文为证）
3. 最后给出分数

**优势**：v2.50.2 已部分采用，可进一步强化
**风险**：输出 token 增加；如果 CoT 步骤太多，LLM 可能走形式

## 优先级判断

### 优先尝试（低成本快速验证）

**D. 指令位置优化** — 1 天内可验证
- 改动最小，只调整 prompt_builder 的拼接顺序
- 如果有效 → 确认注意力稀释是主因
- 如果无效 → 排除此假设，节省后续在此方向的投入

**E. 强化 CoT 锚定** — 1-2 天可验证
- v2.50.2 已部分采用，可进一步强化
- 要求模型逐条回答"是否存在 X 现象？引用原文哪一句为证？"
- 如果模型被迫找证据但找不到，更可能给低分

### 暂缓

**B. 两阶段评分** — v2.51 失败说明"让 AI 先做判断"工程难度高。除非 Stage 1 任务定义极其具体（"找出方法论描述段落"而非"判断方法论是否空泛"），否则容易重蹈覆辙。

### 不建议

**A/C（分段输入/摘要前置）** — 法学论文的论证质量需要全局视角，分段或摘要会丢失关键上下文。

## 实验计划：D 方向快速验证

### 实验目标

验证假设：将扣分规则放在论文内容之后（利用 recency bias），能否提升扣分规则的触发率。

### 实验设计

**对照组**：当前 v2.50.2 结构
```
[维度评分指令 + 扣分规则] + [论文全文] + [参考文献]
```

**实验组**：指令后置结构
```
[维度基础评分指令] + [论文全文] + [参考文献] + [扣分规则 + 强制检查提醒]
```

### 变量控制

- 仅改变扣分规则的位置，不改变规则内容
- 针对 analytical_framework 和 conclusion_consensus 两个问题维度
- 其他 4 个维度保持不变（作为内部对照）

### 测试样本

使用 calibration-regression 集中已知表现不佳的样本：
- 邵莉莉（analytical_framework 预期 < 65，v2.50.2 实际 64 但 v2.53/54 回升）
- 另选 1-2 个在这两个维度得分异常高的负样本

### 成功标准

- 实验组在目标维度的得分比对照组低 10+ 分 → 方向有效，值得深入
- 实验组得分无显著变化（±5 分内）→ 注意力稀释不是主因，转向 E 方向

### 实现方式

在 prompt_builder.py 中增加一个可配置的 `instruction_placement` 参数：
- `"before"`（默认，当前行为）
- `"after"`（实验组，扣分规则后置）

框架 YAML 中通过维度级配置控制：
```yaml
dimensions:
  - name: analytical_framework
    instruction_placement: "after"  # 实验标记
    prompt_template: "..."          # 基础评分指令
    post_content_rules: "..."       # 后置扣分规则（新字段）
```

## 实验计划：E 方向（如 D 无效则跟进）

### 强化 CoT 的具体做法

在 output_template 中增加强制检查步骤：

```
在评分前，你必须逐条回答以下问题（每条必须引用论文原文）：

1. 论文是否提出了可操作的分析框架？引用具体段落。
2. 该框架是否有明确的适用条件和边界？引用具体段落。
3. 如果找不到上述内容，说明"未找到"。

基于以上回答，再进行评分。如果第 1 或第 2 条回答为"未找到"，
则该子项得分上限为 60 分。
```

### 与 v2.51 的区别

v2.51 让 AI 判断"是否存在空泛表述"（抽象判断）。
E 方向让 AI 回答"能否找到具体段落"（具体提取）。找不到 = 扣分，无需 AI 做质量判断。
