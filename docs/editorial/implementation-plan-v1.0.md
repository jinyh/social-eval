# 编辑辅助预审实施计划 v1.0

## M1：业务底座

- 数据模型和 Alembic 迁移；
- 三个初始编辑单元；
- 编辑单元成员权限；
- 单篇/批量投稿、责任编辑和审计；
- 匿名化派生文本及人工确认状态；
- 四档决定纯函数和版本化决定记录。

验收：SQLite API 测试覆盖跨单元拒绝、外部稿号唯一、决定锁定和管理员审计访问。

## M2：评价编排

- 编辑流强制六维 R1/R2；
- 公共预检暂停/继续；
- 独立期刊适配性检查；
- 五轴两轮结果入库；
- `std > 8` 专家门禁；
- 阶段检查点和失败重试。

验收：使用假 providers 完成端到端测试，不调用真实模型。

## M3：意见与报告

- 四模型逐维结果、真实分歧计数和一份综合摘要；
- 专家独立评阅锁定后再开放四模型对照；
- 编辑意见草稿/提交/版本；
- 规范 JSON 和不可变 PDF；
- 站内及无正文邮件通知。

## M4：工作台与管理后台

- 编辑投稿列表和详情；
- 暂停节点处理；
- 报告、专家复核和决定交互；
- 期刊、编辑单元、成员和启用管理。

## M5：验证与上线

- 人工确认的 label manifest；
- 离线问题点匹配和决定指标；
- 本地完整测试；
- 云端预发布，仅使用脱敏测试稿；
- 三个编辑单元分别完成试运行验证和启用签字；
- 新旧六维模型集使用同一批授权样本并行运行，候选结果不得覆盖生产快照。

## 发布门槛

- 不存在已知跨编辑单元越权；
- 生产 Secret 不进入镜像或仓库；
- 数据库与文件已完成可恢复备份演练；
- 编辑流不会将原稿正文发给 provider；
- 任何智能结果都不能自动形成期刊正式决定。
