# 期刊编辑辅助预审系统需求规格 v1.1

> 日期：2026-07-24
>
> 状态：已确认的实现基线
>
> 前版：`editorial-pre-review-requirements-v1.0.md`

## 1. 产品目标

系统为期刊编辑提供未发表法学投稿的 AI 辅助初筛、证据整理和意见草拟能力。
系统不替代编辑或专家作学术终审，也不自动形成期刊决定。

初始编辑单元：

- 《交大法学》；
- 《学术月刊》法学板块；
- 《东方法学》。

管理员可新增期刊和编辑单元。新增单元只能选择已经部署并通过评审的法学模板，
不能在管理界面直接修改 Prompt 或评分规则。

## 2. 用户和权限

### 2.1 管理员

- 跨期刊查看组织、成员、任务状态和审计记录；
- 因运维或合规需要访问稿件和内部报告，所有访问必须审计；
- 新增期刊、编辑单元、成员和版本化政策；
- 重试失败任务、以理由重新打开已锁定决定；
- 按编辑单元批准从“试运行”转为“正式启用”。

### 2.2 编辑

- 只能访问其有效成员关系所属的编辑单元；
- 同一编辑单元成员可查看稿件；每篇稿件有一名责任编辑；
- 责任编辑或管理员可提交正式决定；
- 转移责任编辑、绕过专家门禁和继续被预检暂停的稿件均须填写理由并审计。

### 2.3 专家

沿用现有专家角色，仅能访问明确分配给自己的复核任务。专家先完成并锁定独立评阅，
之后才能看到四个匿名模型的结果并逐项对照。专家原始评分与智能评分并行保存，
不融合覆盖。

作者/投稿人端不在 v1 范围内。

## 3. 投稿与文档

- 支持单篇和批量上传 PDF、DOCX、TXT；
- 系统自动生成投稿 ID；允许填写编辑单元内唯一的外部稿号；
- 原稿不可覆盖，匿名化稿作为派生文档另存；
- 送入外部模型前移除作者、机构、联系方式和可识别元数据；
- 每篇匿名稿均暂停并由编辑网页预览确认后继续；自动检查只提供风险提示，
  不代替人工匿名确认；
- v1 不支持扫描 PDF OCR，应提示上传可解析版本。

## 4. 评审流程

```text
queued
  → anonymizing
  → awaiting_anonymization_confirmation
  → formal_check
  → awaiting_formal_check_confirmation（可选）
  → prechecking
  → awaiting_precheck_confirmation（可选）
  → journal_fit_check
  → awaiting_fit_confirmation（可选）
  → evaluating
  → generating_opinions
  → expert_review（按门禁）
  → awaiting_editor
  → completed
```

失败任务进入 `recovering`，人工关闭进入 `closed`。各阶段必须可重试且不得删除
历史结果。

学术公共预检与期刊适配性检查必须分开。任一检查认为明显不适格时暂停：

- 编辑确认后可直接形成退稿草案；
- 编辑填写理由后可继续完整评价；
- 继续行为不改变原始检查结果。

## 5. 评价继承与期刊可配置项

### 5.1 不可按期刊修改

- 六维 R1 及其公共分档；
- 冻结的六维 R2；
- 五轴位置归属度；
- CCB 协议；
- 原始模型输出、模型分、均值和标准差。

六维、五轴相互独立。五轴不进入决定，CCB 只作参考。

### 5.2 可按编辑单元修改

- 期刊适配性检查配置；
- 优良中差组合到四档建议决定的映射；
- 报告显示和意见模板；
- 通知收件范围；
- 试运行 / 正式启用状态。

规则变更必须形成配置版本，不得覆盖历史版本。

### 5.3 两阶段四档决定

预审阶段：

- 不送外审；
- 修改后重投；
- 送外审；
- 优先送外审。

外审后的终审阶段：

- 退稿；
- 重大修改；
- 小修改后录用；
- 直接录用。

默认预审映射：

1. 预检或期刊适配性失败且编辑确认：不送外审；
2. 研究创新性、理论建构力、逻辑连贯性任一为“差”：不送外审；
3. 六维均不低于“良”、逻辑连贯性为“优”、核心四维至少三项为“优”：
   优先送外审；
4. 核心四维和学术共识度均不低于“良”：送外审；
5. 其余：修改后重投。

前瞻延展性只能支持升级到优先送外审，不能导致降档。该映射是初始配置，不是业务代码
中的唯一真源。

## 6. 智能意见与门禁

- 六维实际运行四个模型，编辑端必须如实显示四模型参与数和逐维分歧；
- 基于已持久化的四模型分数、证据和分析只生成一份综合摘要，不重复调用全文生成
  两份伪独立意见；
- 报告按“综合摘要 → 四模型共识/分歧 → 逐维四模型结果”展示；
- 必须明确标注为智能模型意见，不得包装为人类审稿人；
- 模型原始意见不可修改；编辑另建版本化的最终意见；
- 每次模型调用保存 Prompt、原始响应、时间、模型、供应商和失败信息。

出现以下任一情况时，建议决定状态为 `withheld`：

- R2 后任一维度 `std > 8`；
- 必需模型或必需阶段失败；
- 编辑单元仍处于试运行；
- 匿名化、预检或适配性待确认。

系统仍可计算内部候选类别，但不得自动形成编辑决定。编辑可带理由绕过专家门禁，形成
高风险审计事件。

## 7. 专家独立评阅

- 独立评阅阶段不得返回模型分数、模型分析、证据或综合参考分；
- 专家必须填写全部指定维度的独立分数和理由，提交后锁定；
- 解锁四模型结果后，专家可逐项选择认可、不认可或无意见；
- 不认可任一模型判断必须填写对照说明；
- `std > 8` 的维度必须进入专家复核，不能靠增加模型轮次消除分歧。

## 8. 报告、决定和通知

- 规范真源为版本化 JSON；PDF 是不可变派生制品；
- v1 报告仅供内部使用；
- 编辑意见可保存草稿；正式提交后锁定；
- 管理员可带理由重新打开并形成新版本；
- 完成、失败、专家提交、责任编辑转移发送站内通知和邮件；
- 邮件不得包含稿件正文或审稿意见。

## 9. 人工标签评估

- `raw/label/` 仅在本地使用，不进入 Git；
- `.doc` 通过本机 LibreOffice 派生为 `.docx`，保留原件；
- 人工确认的 manifest 是决定标签真源，不在每次运行时从文件名重新推断；
- 未区分小修/直接录用的标签记为 `accept_unspecified`；
- 四分类指标只在已完成四档裁决的子集计算；
- 全样本计算退稿/修改/录用三分类指标；
- 问题点对齐采用离线字符 n-gram TF-IDF、一对一最大匹配、平均最佳匹配、
  `coverage@0.3`、`coverage@0.5` 和问题条数差，不下载外部 embedding。

## 10. 模型升级

- 生产六维模型集保持固定快照；
- 候选模型集只把 GLM 5.1 替换为 GLM 5.2、把 Qwen 3.6 Plus 替换为
  Qwen 3.7 Max 的固定版本，另外两个模型保持不变；
- 五轴模型不随此次升级变更；
- 新旧模型集对同一批授权样本并行运行，候选任务使用独立任务编号和比较组，
  不覆盖生产结果；
- 候选模型集必须完成校准、冻结测试和最终验证，批准后才能切换生产配置；
- 历史评价结果永不回写。

## 11. 验收

- 单元级权限不能通过列表、详情、报告或导出端点越权；
- 原稿不进入模型调用日志，匿名化稿可追溯到原稿但使用独立路径；
- 编辑流强制启用 R2；通用评价 API 默认行为不变；
- 五轴和 CCB 不影响四档决定；
- `std > 8` 时自动建议被扣留并创建专家复核入口；
- 决定提交、责任编辑转移、门禁绕过和管理员重开均有审计记录；
- 三个初始编辑单元可独立从试运行转为正式启用；
- 编辑可看到四个匿名模型，专家在提交独立评阅前看不到任何模型结果；
- 五轴默认只显示总分，展开后显示五个轴及证据；
- 学术共识度出现在六维、综合参考分封顶说明和报告导出中。
