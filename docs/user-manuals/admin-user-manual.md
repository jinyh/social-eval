# 管理员用户手册

## 一、角色边界

管理员负责账户、邀请、期刊、编辑单元、成员关系、验证登记、策略发布、运行状态和
安全处置。期刊策略的学术签署必须由对应编辑单元负责人完成。
管理员可以审计模型实际身份，但不得代替编辑作出学术决定，也不得修改模型原始评分。

## 二、首次登录和双因素认证

管理员首次登录必须设置双因素认证：

1. 输入邮箱和密码。
2. 使用认证器应用扫描页面二维码。
3. 输入认证器生成的六位动态验证码。
4. 离线保存系统生成的十个一次性恢复码。
5. 确认保存后进入后台。

二维码只在首次绑定时出现，之后登录只输入动态验证码或恢复码。恢复码每个只能使用
一次。账户设置中可以用当前密码和动态验证码重新生成恢复码，旧恢复码随即失效。

管理员同时丢失认证器和恢复码时，由受控运维终端运行
`scripts/reset_admin_mfa.py`。该操作会撤销管理员全部会话、接口密钥和旧恢复码，
并写入审计日志。

## 三、用户和邀请

管理员工作台采用左侧导航和右侧工作区。左侧可以收缩，移动端使用抽屉导航，栏目为：

- 系统总览；
- 用户与权限；
- 期刊与编辑单元；
- 期刊策略；
- 启用验证；
- 模型升级验证。

“用户与权限”采用纵向工作流：先显示全宽用户目录，再显示内部成员邀请表单，最后显示
邀请记录；不会把邀请表单和用户目录左右并排。

### 用户目录

管理员可以按姓名、邮箱、角色和状态筛选用户，并执行：

- 调整角色；
- 停用或恢复账户；
- 发送强制密码重置邮件；
- 撤销全部接口密钥。

用户目录把姓名、邮箱和工作单位合并显示在“用户”一列；较窄窗口中的表格可以在卡片
内部横向滚动，不会挤压管理员左侧导航。

安全影响：

- 单独“撤销接口密钥”不影响普通浏览器使用；
- 强制重置密码会让旧密码、旧会话和全部接口密钥立即失效；
- 修改角色或停用账户会让旧会话和全部接口密钥立即失效；
- 系统禁止停用或降级最后一名有效管理员；
- 用户仍承担在办稿件或专家任务时，系统会阻止停用或换角色。

### 邀请内部成员

1. 在用户目录下方的“邀请内部成员”填写受邀邮箱。
2. 选择编辑、专家或管理员角色。
3. 点击“创建邀请”。
4. 在“邀请记录”检查邮件状态和有效期。

邀请只能使用一次。重发邀请会生成新令牌并立即废止旧链接；撤销后不能再激活。

投稿人不通过邀请开通。投稿人应在登录页自行注册并完成邮箱验证。用户目录会显示
投稿人的邮箱验证状态和工作单位；历史投稿人邀请仍可完成，但后台不再创建新的
投稿人邀请。

本机测试环境的正确链接基址是 `https://localhost`。若旧邮件指向
`http://localhost:5173`，在“邀请记录”点击“重新发送”，不要继续使用旧邮件。
本地测试证书可能触发浏览器警告；确认地址确为 `https://localhost` 后可以允许本次
本地访问。正式域名出现证书警告时不得继续，应先修复证书。

## 四、期刊和编辑单元

1. 填写期刊代码和名称。
2. 填写编辑单元代码和名称。
3. 选择已经部署的期刊策略。
4. 点击“创建试运行单元”。
5. 在“成员与启用门禁”选择编辑单元、编辑和成员身份，点击“更新成员”。每个准备
   正式启用的单元至少指定一名“单元负责人”。

所有新建编辑单元一律从“试运行”开始。成员关系按编辑单元隔离；未加入单元的编辑
不能查看该单元稿件。

## 五、“试运行”与“正式启用（生产使用）”如何切换

系统界面中的正式名称是“试运行”和“正式启用”。“正式启用”表示该编辑单元可以在
批准范围内把智能建议用于日常辅助流程，不等于把候选模型自动切换成生产模型。

### 5.1 两个状态的含义

**试运行**

- 系统正常上传、评价、复核、生成报告并保存审计记录；
- 智能建议默认扣留为测试材料，不直接形成编辑决定依据；
- 用于校准、冻结测试、最终验证、故障恢复后的观察。

**正式启用**

- 编辑单元已经完成本单元验证并取得编辑确认；
- 智能建议可以在批准范围内进入正式编辑辅助流程；
- 原始模型结果、专家意见和编辑决定仍分别保留，智能建议不替代人类决定。

### 5.2 从试运行切换为正式启用

业务前置条件：

1. 完成本单元校准、冻结测试和最终验证；
2. 样本清单已经冻结并可计算 SHA-256；
3. 六维框架、五轴配置和生产模型集版本明确；
4. 四模型结果完整，高分歧维度已进入专家复核；
5. 编辑已经检查抽样结果并形成签字意见；
6. SMTP、备份恢复和运行健康检查通过。

后台操作：

1. 打开“成员与启用门禁”。
2. 选择目标编辑单元，确认当前徽标为“试运行”。
3. 填写试运行验证样本数，必须大于 0。
4. 点击“选择样本清单”。系统只在当前浏览器本地计算 SHA-256，不上传清单正文。
5. 填写验证结论和编辑签字说明，至少 5 个字符。
6. 点击“登记验证记录”。
7. 通知对应单元负责人在编辑工作台核对策略和验证证据，并完成签署。
8. 管理员刷新页面，确认显示“单元负责人已经签署”，再点击“使用编辑签署并正式
   启用”。

管理员不能替代编辑签署。验证记录必须与当前试运行策略的框架、模型集、策略版本和
样本摘要完全一致；签署人还必须在启用时仍是该单元的有效负责人。

操作成功后：

- 编辑单元徽标变为“正式启用”；
- 状态变化、验证记录、样本摘要和操作人写入审计日志；
- 历史试运行报告继续保留。

### 5.3 从正式启用退回试运行

出现以下任一情况应退回：

- 关键模型或供应商异常；
- 报告缺维度、少于四个模型或证据错配；
- 专家隔离门禁失效；
- 新模型漂移尚未批准；
- SMTP、数据库、存储或备份出现影响流程可信度的问题；
- 编辑要求暂停正式建议。

后台操作：

1. 在“成员与启用门禁”选择当前“正式启用”的单元。
2. 填写至少 5 个字符的退回原因。
3. 点击“退回试运行”。
4. 在确认框核对目标后确认。

回退只改变后续智能建议的展示门禁，不删除历史稿件、模型调用、专家复核、编辑决定、
验证记录或审计日志。问题修复后必须重新完成最小冒烟和必要验证，不得直接跳回正式
启用。

### 5.4 与模型生产状态的区别

编辑单元状态和模型集状态是两件事。当前默认策略为：

- 处于试运行的编辑单元，新投稿使用 GLM-5.2、Qwen3.7-Max、DeepSeek-v4-Pro、
  Kimi-k2.6 及四模型同级匿名互评；
- 已正式启用的编辑单元继续使用自身已批准的不可变模型策略快照；
- 编辑单元“正式启用”不会自动改写其他单元的模型策略；
- 候选模型任务使用独立记录，不覆盖同一稿件的生产结果；
- 历史投稿继续使用创建时绑定的策略版本，不重新评价、不回写。

## 六、期刊策略管理

1. 从左侧进入“期刊策略”，选择编辑单元和现有策略版本。
2. 核对收稿范围、排除范围、栏目定位、稿件类型和目标读者。
3. 修改版本号，并选择“稳定四模型”或“新四模型试运行”。
4. 草稿点击“保存草稿”；试运行、正式使用或历史版本点击“基于此版本创建草稿”。
5. 点击“冻结并进入试运行”后，内容不可直接修改；任何调整都必须再建新版本。
6. 使用本版本完成样本验证，交由单元负责人签署，再由管理员正式启用。

后台不能修改六维、五轴、综合参考分、分档阈值或评价提示词。页面中的技术策略编号
和内容摘要仅用于审计，不是要求编辑记忆的业务名称。

已启用策略不能原地覆盖。新投稿绑定切换后的新版本，历史投稿继续使用创建时绑定的
不可变策略快照。投稿人只能看到正式启用策略中的收稿范围、栏目定位、稿件类型和
特别说明，看不到内部适配逻辑、模型配置或互评协议。

## 七、六维模型升级验证

1. 在后台确认“当前生产模型集”和“候选验证模型集”。
2. 选择已有且完成生产评价的编辑投稿编号。
3. 点击“创建候选模型并行任务”。
4. 确认候选任务使用同一匿名稿并有独立任务编号。
5. 比较失败率、逐维漂移、标准差、优良中差变化和专家门禁变化。

该功能只用于获授权的校准、冻结测试和最终验证样本。五轴模型保持不变，候选结果
不得覆盖生产报告。

## 八、密码、接口密钥和安全处置

- 管理员不能查看任何用户的旧密码明文。
- 用户怀疑密码泄露时，发送强制密码重置并确认邮件送达。
- 接口密钥疑似泄露时，先撤销密钥；若账户也可能失控，再停用账户。
- 角色调整前检查在办投稿、编辑责任和专家任务。
- 管理员恢复码应由本人离线保存，不得放入工单或普通聊天。

## 九、邮件和邀请故障

排查顺序：

1. 在邀请记录确认邀请仍为“待使用”。
2. 检查邮件投递状态是排队、发送中、已接受还是失败。
3. 核对公开基址是否为实际可访问地址。
4. 本机应为 `https://localhost`；jCloud 应为正式 HTTPS 域名。
5. 修正配置后点击“重新发送”，因为旧邮件不会自动改写。
6. 本机首次访问如遇证书警告，确认地址后只允许本次本地证书；正式环境不允许绕过。
7. 不要从数据库复制令牌；系统只保存令牌哈希，邮件接受后也会清除加密令牌。

## 十、日常运行检查

每天至少检查：

- API 存活和内部就绪状态；
- 停滞处理单元和 Celery 队列深度；
- GLM-5.2 匿名检测调用失败及转人工门禁情况；
- 模型调用失败及重试；
- SMTP 失败与退信；
- PostgreSQL 和独立数据盘容量；
- 最近成功备份是否在 26 小时内；
- 有无长期未完成的专家任务或未处理通知。

上线、备份和恢复操作分别参见：

- `docs/deployment/launch-checklist.md`；
- `docs/deployment/backup-and-recovery-runbook.md`；
- `docs/deployment/CURRENT-HANDOFF.md`。
