# v2.49 框架实施计划：强化致命缺陷检测

**创建日期**：2026-05-14  
**目标**：将专家意见中的批评模式转化为 prompt 中的强制检测规则  
**预计时间**：3-4 小时

---

## 背景

v2.48-optimized 测试结果显示：
- 负样本平均分 85.2（目标 < 75）
- 正负样本差距 2.7（目标 > 15）
- 仲裁机制和换模型都无效

**根本原因**：AI 看形式要素，专家看论证深度。负样本具备形式要素（问题句、框架结构、引用）但缺乏深度。

**解决方案**：在 prompt 中增加负面模式检测，强制识别"格式规范但缺乏深度"的论文。

## Step 2: 问题创新性维度强化（3 个负面模式）

### 位置
文件：`configs/frameworks/law-v2.49-20260514.yaml`  
搜索：`- key: problem_originality`  
修改：`ceiling_rules` 和 `prompt_template`

### 2.1 增加 ceiling_rule：新概念包装旧问题

在 `ceiling_rules` 中添加（在 `material_novelty_without_thesis` 之后）：

```yaml
  - rule_id: problem_originality.new_term_old_problem
    trigger: 用新术语重新描述已有讨论，但未展示新概念相对旧概念的进步或解释力提升
    score_ceiling: 65
    priority: 2
    severity: major
    detection_method: |
      检查论文是否引入新概念/新术语作为核心创新点；
      若是，检查原文是否说明：
      (1) 新概念相对既有概念的理论进步在哪里
      (2) 新概念是否改变了问题的解释路径或规范判断
      (3) 新概念是否只是既有讨论的重新包装
      若只有新术语但无实质推进，触发此规则
    examples:
      - "提出'权利遮蔽'概念，但实质是用新词描述'知情权/申辩权无法实现'这一已有讨论"
      - "引入'XX理论'作为标题，但正文仍是既有观点的复述"
    anti_examples:
      - "新概念明确说明相对既有概念的理论进步（如解释力更强、适用范围更广）"
      - "新概念改变了问题的分析路径或规范判断"
```

### 2.2 强化现有规则：weak_problem_formulation

修改 `weak_problem_formulation` 的 `detection_method`：

```yaml
detection_method: |
  检查问题表述是否过于宏大（如"XX的法律规制""XX法治化"）且无法聚焦具体争点；
  或问题意识薄弱，只宣称"填补空白"但未说明为何是问题。
  【新增】检查是否属于"宏观介绍非深度分析"：
  - 论文完成了体系介绍但未触及现实问题
  - 无不同学者观点的交锋
  - 只是系统归纳既定立场而非提出可争辩的争点
```

### 2.3 强化现有规则：no_justiciable_question

修改 `no_justiciable_question` 的 `detection_method`：

```yaml
detection_method: |
  检查论文是否只描述政策背景，无可争辩的法学问题。
  【新增】检查是否属于"主题声明非研究问题"：
  - 全文主要是阐释既定立场（如"爱国主义的法治建设"）
  - 无可争辩的法学争点，只是权威表述的系统归纳
  - 只要全文主要是在阐释既定立场而非提出可争辩的法学争点，
    就不得因为主题重大而给高分
```

### 2.4 修改 prompt_template

在 `prompt_template` 的"第一步：可争辩性检查"之后，增加：

```
【负面模式强制检测】：
在给出最终分数前，必须检查以下负面模式：

1. 新概念包装旧问题：
   - 论文是否引入新概念/新术语作为核心创新点？
   - 若是，原文是否说明新概念相对既有概念的理论进步？
   - 若只有新术语但无实质推进 → 触发 new_term_old_problem，上限 65 分

2. 宏观介绍非深度分析：
   - 论文是否完成了体系介绍但未触及现实问题？
   - 是否无不同学者观点的交锋？
   - 若只是系统归纳既定立场 → 触发 weak_problem_formulation，上限 65 分

3. 主题声明非研究问题：
   - 全文是否主要是阐释既定立场（如政策倡导）？
   - 是否无可争辩的法学争点？
   - 若只是权威表述的系统归纳 → 触发 no_justiciable_question，上限 50 分
```

## Step 3: 分析框架建构力维度强化（4 个负面模式）

### 位置
文件：`configs/frameworks/law-v2.49-20260514.yaml`  
搜索：`- key: analytical_framework`  
修改：`ceiling_rules` 和 `prompt_template`

### 3.1 增加 ceiling_rule：口号式呼吁

在 `ceiling_rules` 中添加（在 `framework_unused` 之后）：

```yaml
  - rule_id: analytical_framework.slogan_advocacy
    trigger: 空谈义务、权利、责任，无具体制度方案或裁判规则；或大量使用"应当""必须"等规范性表述但无操作化路径
    score_ceiling: 60
    priority: 2
    severity: major
    detection_method: |
      检查论文是否大量使用规范性表述（"应当""必须""需要"）；
      若是，检查是否提供：
      (1) 具体的制度设计方案
      (2) 可操作的裁判规则或程序衔接
      (3) 法学层面的操作化路径
      若只有口号式呼吁而无具体展开，触发此规则
    examples:
      - "应当完善XX制度、加强YY保护"，但无具体制度方案
      - "空谈义务、权利、责任，在论证深度上存在很大缺陷"
    anti_examples:
      - "提出具体的裁判规则：当XX情形时，应采用YY解释路径"
      - "给出制度设计方案：建议在ZZ条件下设立AA机制"
```

### 3.2 增加 ceiling_rule：概念堆砌

```yaml
  - rule_id: analytical_framework.concept_stacking
    trigger: 大量使用术语（如"监管合作主义""穿透式监管""监管试验主义"）但无定义或操作化
    score_ceiling: 55
    priority: 1
    severity: critical
    detection_method: |
      检查论文是否使用≥3个专业术语/理论概念作为核心框架；
      若是，检查每个核心术语是否：
      (1) 有明确的法学界定或定义
      (2) 有分析步骤或操作化路径
      (3) 在后文中被真正调用（≥2次）
      若核心术语堆砌但无定义或操作化，触发此规则
    examples:
      - "大量使用'监管合作主义''穿透式监管''监管试验主义'等概念进行堆砌，并未对这些概念作出详细解释"
      - "引入多个理论概念但只在绪论出现，后文未真正调用"
    anti_examples:
      - "每个核心概念都有法学界定，并在后文分析中被反复调用"
```

### 3.3 增加 ceiling_rule：理论与制度脱节

```yaml
  - rule_id: analytical_framework.theory_practice_gap
    trigger: 引入理论框架但未真正用于分析，或理论与后文制度设计脱节
    score_ceiling: 70
    priority: 3
    severity: minor
    detection_method: |
      检查论文是否引入跨学科理论（如社会技术系统理论、经济学理论）；
      若是，检查：
      (1) 理论是否在后文分析中被真正调用
      (2) 理论与制度设计之间的连接是否清晰
      (3) 理论是否只是装饰性引用
      若理论与制度设计脱节，触发此规则
    examples:
      - "以社会技术系统理论作为分析视角，但该理论与后文算法审计制度之间的连接并不算强"
      - "引入XX理论但只在绪论出现，后文制度设计未体现理论指导"
    anti_examples:
      - "理论在后文每个制度设计环节都被明确调用"
      - "理论与制度设计之间有清晰的推导路径"
```

### 3.4 强化现有规则：no_operational_framework

修改 `no_operational_framework` 的 `detection_method`：

```yaml
detection_method: |
  检查核心术语是否有定义、是否有分析步骤、是否有法学转化。
  【新增】检查是否属于"宏观介绍非深度分析"：
  - 论文完成了体系构建的宏观介绍
  - 但未触及该体系在现实中面临的具体问题
  - 无不同学者观点在此的交锋
  若只是宏观介绍而无深度分析，触发此规则
```

### 3.5 修改 prompt_template

在 `prompt_template` 的"第一步：框架可操作性检查"之后，增加：

```
【负面模式强制检测】：
在给出最终分数前，必须检查以下负面模式：

1. 概念堆砌无操作化：
   - 论文是否使用≥3个专业术语作为核心框架？
   - 每个核心术语是否有定义、分析步骤、后文调用？
   - 若核心术语堆砌但无操作化 → 触发 concept_stacking，上限 55 分

2. 口号式呼吁无具体展开：
   - 论文是否大量使用"应当""必须"等规范性表述？
   - 是否提供具体的制度方案或裁判规则？
   - 若只有口号式呼吁 → 触发 slogan_advocacy，上限 60 分

3. 理论与制度脱节：
   - 论文是否引入跨学科理论？
   - 理论是否在后文分析中被真正调用？
   - 若理论与制度设计脱节 → 触发 theory_practice_gap，上限 70 分

4. 宏观介绍非深度分析：
   - 论文是否只完成体系介绍但未触及现实问题？
   - 是否无不同学者观点的交锋？
   - 若只是宏观介绍 → 触发 no_operational_framework，上限 50 分
```

## Step 4: 结论可接受性维度强化（2 个负面模式）

### 位置
文件：`configs/frameworks/law-v2.49-20260514.yaml`  
搜索：`- key: conclusion_consensus`  
修改：`ceiling_rules` 和 `prompt_template`

### 4.1 增加 ceiling_rule：生搬硬套

在 `ceiling_rules` 中添加（在 `vague_recommendations` 之后）：

```yaml
  - rule_id: conclusion_consensus.mechanical_application
    trigger: 结论从立法、司法、执法、守法四个方面生搬硬套，无法令人接受
    score_ceiling: 60
    priority: 2
    severity: major
    detection_method: |
      检查结论是否采用"立法-司法-执法-守法"四分法或类似机械框架；
      若是，检查：
      (1) 每个方面是否有具体的制度方案或论证
      (2) 四分法是否与正文论证有机衔接
      (3) 是否只是套用框架而无实质内容
      若生搬硬套无法令人接受，触发此规则
    examples:
      - "在结论上试图建立起一套XX实施的法律体系，从立法、司法、执法、守法四个方面开展论述，完全是生搬硬套"
      - "套用标准框架但每个方面都只有空泛表述"
    anti_examples:
      - "四分法与正文论证有机衔接，每个方面都有具体论证"
```

### 4.2 增加 ceiling_rule：结论不足以支撑主张

```yaml
  - rule_id: conclusion_consensus.insufficient_support
    trigger: 引入新理论/新框架但未给出令人满意的足以替代既有理论的效果
    score_ceiling: 70
    priority: 3
    severity: minor
    detection_method: |
      检查论文是否提出新理论/新框架作为既有理论的替代方案；
      若是，检查：
      (1) 新理论是否明确说明相对既有理论的优势
      (2) 新理论是否能解决既有理论无法解决的问题
      (3) 新理论是否足以形成成熟的权利义务配置方案
      若新理论不足以替代既有理论，触发此规则
    examples:
      - "虽然引入身份分层理论来试图解决人格权商业化利用上既有理论所面临的困境，但是并未对此给出一个令人满意的足以替代既有理论的效果"
      - "提出新框架但未说明相对既有方案的优势"
    anti_examples:
      - "新理论明确说明相对既有理论的优势，并能解决既有理论的核心困境"
```

### 4.3 修改 prompt_template

在 `prompt_template` 的"第三步：确定分数"之前，增加：

```
【负面模式强制检测】：
在给出最终分数前，必须检查以下负面模式：

1. 生搬硬套无法令人接受：
   - 结论是否采用"立法-司法-执法-守法"等机械框架？
   - 每个方面是否有具体论证还是只有空泛表述？
   - 若生搬硬套 → 触发 mechanical_application，上限 60 分

2. 结论不足以支撑主张：
   - 论文是否提出新理论作为既有理论的替代方案？
   - 新理论是否明确说明相对既有理论的优势？
   - 若新理论不足以替代 → 触发 insufficient_support，上限 70 分
```

## 风险与缓解

### 风险 1：规则过于严格，误伤正样本

**缓解**：
- 在 Step 5 验证后，用 3 篇正样本回归测试
- 如果正样本平均分 < 85，说明规则过严，需要调整

### 风险 2：规则仍然无效，负样本得分仍高

**缓解**：
- 分析未触发原因（prompt 表述不够明确？检测条件过严？）
- 考虑更激进的策略：降低上限分数（如 concept_stacking 从 55 降至 45）

### 风险 3：模型无法理解负面模式描述

**缓解**：
- 在 prompt 中增加具体示例（从专家意见中提取）
- 使用更明确的检测条件（如"≥3个术语无定义"）
