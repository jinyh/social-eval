# v2.51 Phase 0 失败报告

## 版本信息
- **版本**: v2.51
- **测试时间**: 2026-05-15 ~ 2026-05-17
- **测试方法**: Autoresearch 自动迭代优化（7 次迭代）
- **测试样本**: 10 篇负样本 + 3 篇正样本

## 执行摘要

v2.51 Phase 0（Stage A 负面模式检测器 dry-run）**未通过验证**。经过 7 次迭代优化，最佳结果仍远低于目标：

| 指标 | 目标 | 最佳结果 (Iter 4) | 差距 |
|------|------|-------------------|------|
| 负样本命中率 | ≥ 70% | 22.2% | -47.8% |
| 正样本误报率 | ≤ 10% | 50.0% | +40.0% |
| Metric | ≥ 0.0 | -0.778 | -0.778 |

**结论**: 当前 Stage A 检测器架构无法达到生产要求，建议暂停 Phase 0，重新设计 pattern 定义。

## 关键发现

### 1. Pattern 定义问题

**`conclusion_consensus` 的 3 个 pattern 几乎完全无效**：
- `mechanical_application`（机械套用固定框架）：0% 触发率
- `direction_only_suggestion`（方向性建议）：Iteration 4 后有改善，但仍然漏报严重
- `insufficient_justification`（缺乏论证支撑）：0% 触发率

**原因分析**：
- Pattern 描述过于抽象，AI 难以准确判断
- 缺少可观察的客观指标（如"统计规范性表述数量"这类机械化检查）
- 正负样本的区分依赖于"论证质量"而非"表面特征"

### 2. 批量检测 vs 单 pattern 模式

**批量模式**（Baseline ~ Iter 5）：
- 一次 AI 调用检测一个维度的所有 pattern
- 命中率低（11-22%），误报率中等（50-67%）
- AI 倾向于对所有 pattern 给出相似判断（要么全触发，要么全不触发）

**单 pattern 模式**（Iter 6-7）：
- 每个 pattern 独立调用 AI
- 命中率提升（33%），但误报率暴增（83%）
- AI 对每个 pattern 都更容易触发，无法区分正负样本

**结论**：单 pattern 模式提高了检测灵敏度，但同时也放大了 pattern 定义的缺陷。

### 3. min_confidence 阈值无效

**Iteration 3**：降低 min_confidence 到 0.50 → 命中率反而下降（22% → 11%）
**Iteration 7**：提高 min_confidence 到 0.75/0.80 → 误报率完全不变（83%）

**原因**：AI 对所有论文（无论正负）都倾向于给出高置信度的判断。`min_confidence` 无法作为区分正负样本的有效手段。

### 4. Prompt 优化边际收益递减

**有效的优化**（Iteration 4）：
- 简化 `direction_only_suggestion` 的 prompt
- 从"统计条目 + 检查 3 个条件"改为"识别方向性表述 vs 具体方案"
- 误报率从 66.7% 降到 50.0%

**无效的优化**（Iteration 1, 2, 5）：
- 修改 prompt 措辞、调整检测逻辑
- 结果高度不稳定（同样的策略在不同 pattern 上效果完全不同）

**结论**：Prompt 优化只能解决表面问题，无法解决 pattern 定义的根本缺陷。

## 根本原因分析

### 问题：AI 无法区分"正常学术表述"和"空泛表述"

**案例 1：`direction_only_suggestion`（方向性建议）**

- **负样本**（李姝卉）：结论只说"应当完善""需要加强"，缺少具体方案
- **正样本**（杜宴林）：结论也有"应当"等表述，但建立在扎实论证基础上

AI 看到"应当"就触发，无法判断背后是否有论证支撑。

**案例 2：`slogan_advocacy`（口号式呼吁）**

- **负样本**（邵莉莉）：大量"应当""必须"，但无具体法条或制度设计
- **正样本**（郑晓剑）：也有规范性表述，但每个表述都有具体论证

AI 统计"应当"的数量，但无法判断是否有"具体展开"。

### 根本矛盾

**Pattern 检测需要的能力**：
1. 识别表面特征（如"应当""必须"等关键词）
2. 判断是否有论证支撑（需要理解全文论证质量）

**AI 实际能力**：
- ✅ 擅长识别表面特征
- ❌ 难以判断论证质量（需要深度理解，而 Stage A 的短 prompt 无法提供足够上下文）

**结论**：当前 Stage A 架构（短 prompt + 负面模式检测）无法完成"判断论证质量"这一核心任务。

## 经验教训

### 1. Pattern 定义必须基于可观察指标

**失败案例**：
- "结论缺乏充分论证支撑" — 过于抽象，AI 无法判断
- "建议停留在方向性层面" — 需要判断"是否有具体方案"，主观性强

**成功案例**（v2.50.1 问题创新性）：
- "统计规范性表述数量" — 机械化，可观察
- "检查是否有对应的具体法条" — 明确的检查项

**教训**：Pattern 定义应该像"检查清单"，而不是"质量判断"。

### 2. 短 prompt 无法替代深度理解

v2.51 的设计初衷是用短 prompt（~100 行）避免长 prompt 中的指令被淹没。但短 prompt 也意味着：
- AI 缺少足够上下文理解论文整体质量
- 无法判断"表面特征"背后的"论证质量"

**教训**：负面模式检测不适合用短 prompt。如果需要判断论证质量，必须提供足够上下文。

### 3. Autoresearch 适合参数优化，不适合架构修正

Autoresearch 在以下场景有效：
- ✅ 优化 prompt 措辞（Iteration 4 成功）
- ✅ 调整阈值参数（如果参数有效的话）

Autoresearch 在以下场景无效：
- ❌ Pattern 定义方向性错误（需要人工重新设计）
- ❌ 架构性缺陷（如批量检测 vs 单 pattern 模式的权衡）

**教训**：在 pattern 定义稳定之前，不应该用 autoresearch 优化。

## 下一步建议

### 短期：回退到 v2.50.2

**理由**：
- v2.50.2 已经达到：负样本均值 76.1，正负差距 15.0，识别率 44%
- v2.51 Phase 0 经过 7 次迭代，最好结果仍然是 metric = -0.778（远低于 v2.50.2）
- 继续优化的边际收益很低，每次迭代成本很高（40 分钟/次）

**行动**：
1. 将 v2.50.2 标记为当前生产推荐版本
2. 更新 CLAUDE.md 中的"当前活跃版本"
3. 归档 v2.51 Phase 0 的测试结果

### 中期：重新设计 pattern 定义

**目标**：提取更具体的可观察指标，避免依赖"论证质量判断"

**方法**：
1. 深入分析专家意见，识别可机械化检查的特征
   - 例如："统计'应当'出现次数" ✅
   - 而非："判断建议是否有论证支撑" ❌
2. 小规模验证（2-3 个 pattern，5 篇论文）
   - 目标：70% 命中率 + 10% 误报率
   - 只有达到目标才扩展到全部 6 个 pattern
3. 参考 v2.50.1 问题创新性的成功经验
   - 前置扣分制 + 具体检查项 + 明确扣分规则

### 长期：重新评估两阶段架构

**问题**：Stage A（短 prompt）+ Stage B（长 prompt）的架构可能不适合"判断论证质量"这类任务。

**备选方案**：
1. **单阶段架构**：回到 v2.50.2 的"嵌入评分步骤"模式，在长 prompt 中直接扣分
2. **混合架构**：
   - Stage A 只检测机械化指标（如"统计关键词数量"）
   - Stage B 负责判断论证质量，并在 prompt 中明确引用 Stage A 的统计结果
3. **放弃 pattern 检测**：直接在维度评分 prompt 中加强扣分指令，配合代码层 ceiling
