# law-ai-assisted-review-rules v0.14 复核意见

**评审对象**：`docs/evaluation/law-ai-assisted-review-rules-v0.14-expert-edition.md`  
**评审日期**：2026-05-08  
**评审重点**：评审流程合理性、冗余风险、AI 辅助评审能力边界、多模型与 autoresearch 使用方式

---

## 1. 总体判断

v0.14 相比前序版本的主线更清楚，尤其是把"项目口径预检"、"六维评分"、"自主知识体系信号校验"和"评价层复核判断"拆成四个阶段，并区分"预检层复核"与"评价层复核"，这是正确方向。

但当前版本仍有四组概念需要进一步切开，否则落地时容易出现执行口径不一致、专家复核工作量失控或高估 AI 能力的问题：

1. **校准期 / 正式运行期**
2. **轻量质检 / 专家深审**
3. **项目口径预检 / 自主知识体系信号校验**
4. **多模型暴露分歧 / 多模型缩小分歧**

建议 v0.15 优先处理上述四组关系，而不是继续增加更多评分细则。

---

## 2. 需要修正的判断

### 2.1 "明显不适格"不是绝对冲突，而是缺少运行阶段区分

当前主流程写法是：

- 明显不适格：输出预检说明，人工确认，结束
- 不进入六维评分

但附录 A 又写：

- 预检校准完成前，不得将"明显不适格"结果作为自动拒稿、自动剔除样本或终止六维参考评分的依据

这两者可以共存，但文档必须显式区分：

- **校准期**：明显不适格仍可继续跑六维参考评分，用于检验预检门槛是否过严、六维评分是否能兜底。
- **正式运行期**：明显不适格只输出预检报告和人工确认任务，不进入正式六维评分和候选排序。

如果不区分校准期和正式运行期，执行团队会不知道"明显不适格"到底应当终止，还是继续评分。

### 2.2 "边界论文必须复核"应改成分层复核，而不是一律专家深审

v0.14 规定边界论文进入六维评分，并且无论评分如何都自动触发专家复核。这个方向有合理性，因为边界论文确实不应由 AI 直接裁断。

问题在于，文档没有区分：

- **边界质检**：轻量人工确认，主要判断是否进入候选池或是否需要继续观察。
- **专家深审**：完整专家评审，适用于高潜力、高争议或高风险论文。

如果所有边界论文都进入完整专家深审，第一阶段压缩工作量的目标会被削弱。更合理的机制是：

- 边界论文默认进入"人工质检池"。
- 只有边界论文同时满足高分、高自主知识体系信号、关键维度高分歧、重大制度议题或质量风险时，才进入完整专家深审。

## 3. 需要补充的风险

### 3.1 "研究创新性"与"问题创新性"术语需统一

v0.14 使用"研究创新性"，但项目上下文和部分既有框架使用"问题创新性 / Problem Originality"。

这不是单纯文字差异。后续落到 YAML 配置、JSON 输出、报告字段和统计分析时，如果两个名称并存，可能造成字段映射混乱。

建议：

- 文档正文统一使用一个主名。
- 如果保留历史兼容，可写成："研究创新性（原：问题创新性 / Problem Originality）"。
- JSON 字段和配置文件只保留一个稳定字段名。

### 3.2 项目口径预检与自主知识体系信号校验仍有重复

两处检查内容高度接近：

- 预检查：中国问题、法学问题、中国实践解释、理论转化或可复核命题。
- 信号校验查：中国问题中心性、中国实践解释尝试、外部理论转化、可复核概念或命题。

这种重复不一定要删除，但必须明确职责差异：

- **预检阶段**只判断论文是否有最低进入资格，结论是"进入评分 / 边界进入评分 / 明显不适格"。
- **信号校验阶段**只整理证据强度、风险和六维评分矛盾，不再重新判断是否适格。
- **复核判断阶段**统一决定是否进入人工复核，信号校验阶段不直接作最终复核裁断。

这样可以保留双重检查的价值，同时避免同一套信号在两个阶段反复作筛选。

### 3.3 输出规范需要区分不同流程分支

v0.14 规定最终报告必须输出基础分、前瞻延展性加分、结论可接受性上限、最终分等字段。

但"明显不适格"分支不进入六维评分，因此无法自然产生这些字段。

建议将输出规范拆成两类：

- **预检终止报告**：只包含预检结论、证据片段、人工确认状态、明显不适格原因。
- **完整评价报告**：包含六维评分、总分协议、自主知识体系信号、复核判断和分流建议。

如果处于校准期且明显不适格仍跑六维参考评分，应标记为"参考评分"，不得进入正式候选排序。

## 4. AI 能力边界与多模型策略

### 4.1 AI 真实可做的部分

AI 适合承担以下任务：

- 抽取文内证据和段落位置。
- 初步识别是否存在中国问题、法学问题、理论转化动作或可复核命题。
- 检查是否只有政策复述、概念标签、材料堆砌或口号式表达。
- 标记明显论证断裂、材料与结论错位、概念前后不一致。
- 生成结构化初筛报告，帮助专家快速定位风险。

这些任务的共同特点是：主要依据文内可观察信号，不要求 AI 裁定学术史地位、真实首创性或长期影响。

### 4.2 AI 不应承担的部分

AI 不适合承担以下任务：

- 裁定论文是否真正构建中国自主法学知识体系。
- 裁定论文真实首创性或长期学术影响。
- 判断论文是否具有文化主体性或政治正确性。
- 用多模型投票替代专家判断理论型、文化阐释型、制度立法型论文。
- 通过在线协商或 autoresearch 消除模型之间的底层学理偏好差异。

这些任务涉及学术共同体判断、长期影响判断或高度语境化的规范评价，必须交由专家处理。

### 4.3 多模型应定位为"暴露分歧"，不是"缩小分歧"

当前项目已有测试结论显示，holdout 集中的高分歧主要来自模型级系统性理解差异，而不是规则不够细。偏离传统法学论证型越远，三模型分歧越大；理论建构型、文化阐释型、制度立法型和跨文化比较法型论文尤其明显。

因此，不建议将"3-4 个大模型同时评价"表述为缩小评审结果差异的核心手段。更稳妥的表述是：

> 多模型并发用于暴露不确定性和触发复核，而不是假定模型间能够自然收敛。

执行上建议：

- 多模型输出保留原始分、均值、标准差和分歧说明。
- 标准差或关键维度分歧超过阈值时，自动触发人工复核。
- 不把多模型均值包装成更客观的"最终分"。
- 对理论型、文化阐释型、特殊制度议题论文，应预期更高分歧，并把分歧本身作为专家关注点。

### 4.4 Autoresearch 应定位为离线规则优化工具

Autoresearch 可以用于：

- 离线探索 prompt / rubric 的优化方向。
- 在校准集上发现规则表述含混、输出格式不稳定或维度错位问题。
- 辅助生成候选改动，再由人工审查后进入验证集测试。

Autoresearch 不应被定位为：

- 在线评审阶段的收敛机制。
- 消除多模型学理差异的工具。
- 持续针对 holdout 或 validation 单篇结果调参的机制。

建议写入规程的口径是：

> Autoresearch 仅用于离线规则迭代和验证脚本驱动的提示词优化；正式评审中，多模型分歧应作为可靠性信号保留，并进入复核判断，不通过自动迭代强行收敛。

## 5. 建议的 v0.15 修改方向

### 5.1 流程结构

建议把流程改成以下口径：

```text
论文输入
  ↓
项目口径预检
  ├─ 进入评分 → 六维评分
  ├─ 边界进入评分 → 六维评分 + 标记人工质检
  └─ 明显不适格
       ├─ 校准期：继续跑六维参考评分 + 人工确认
       └─ 正式期：输出预检终止报告 + 人工确认
  ↓
六维评分
  ↓
自主知识体系信号校验（只做证据与风险整理）
  ↓
统一复核判断
  ├─ 无需复核
  ├─ 人工质检
  └─ 专家深审
```

### 5.2 复核触发

建议将复核拆成三档：

1. **无需复核**：预检通过，六维评分稳定，自主知识体系信号与评分一致，无重大风险。
2. **人工质检**：边界论文、明显不适格人工确认、轻度信号矛盾、抽样质量控制。
3. **专家深审**：高潜力高争议论文、关键维度分歧大、重大制度议题风险、材料与结论严重错位、外部验证冲突。

这样比"复核 / 不复核"二分更适合 2000 篇三大刊论文的实际工作量。

### 5.3 多模型和阈值

建议补入明确阈值：

- `std <= 5`：高置信度。
- `5 < std <= 8`：中等置信度，进入观察或抽样质检。
- `8 < std <= 12`：低置信度，进入人工质检或专家复核。
- `std > 12`：关键分歧，原则上进入专家深审。

如果后续采用单锚模型策略，也应保留少量多模型抽检，用于监测模型漂移和关键类型论文的不稳定性。

---

## 6. 最终建议

v0.14 不需要继续堆叠更多细则。当前最重要的工作是把流程治理规则写清楚：

- 校准期和正式运行期分开。
- 边界质检和专家深审分开。
- 预检只管准入，信号校验只管证据与风险。
- 多模型用于暴露分歧，autoresearch 用于离线优化，不把二者写成自动收敛机制。

完成这些调整后，v0.14 的流程会更可执行，也更符合 AI 辅助评审的真实能力边界。
