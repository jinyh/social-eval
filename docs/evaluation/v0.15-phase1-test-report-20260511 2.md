## 1. 测试结论

**管线层面**：v2.45 四阶段管线（项目口径预检 → 六维评分 → 自主知识体系信号校验 → 评价层复核判断）端到端跑通。脚本 `scripts/run_v0.14_multi_model_test.py` 修复两处工程缺口后，产出严格符合 v0.15 规程 §7.2 / §7.3 契约。

**稳定性层面**：GLM + Qwen 并发 avg_std=3.35、weighted_total_mean=85.67，与 v2.44 baseline 同量级；GPT-5.5 复核在 1/4 篇上触发（法典化_周光权），机制按设计工作。

**策略判定**：位于 v0.14 测试方案的**方案 B 区间**（三/双模型 std 8-12 + GPT 复核有效），GLM + Qwen + GPT-5.5 复核作为第一阶段生产策略具备证据。

前 5 维偏差均在 5 分内，属于 temperature=0.3 单次抽样的正常波动范围。

### 5.2 forward_extension 异常波动

周光权论文在 v2.44 给 37.5、v2.45 给 77，**同一 prompt、同一模型、同一温度**下结果差异达 39.5 分。根因：

- v2.44 run：glm=25（触发 `slogan_outlook` 上限规则），qwen=50
- v2.45 run：glm=92，qwen=62

两个模型在这一维度上都存在"是否判触发上限规则"的不稳定。好消息是：**v2.45 管线的 GPT 复核机制刚好在这里触发**（std=21.2 > 12），由 GPT-5.5 给出独立判断 69 分，综合 mean 回落到 74.3。这恰好验证了 v0.15 规程 §6.1.2 "评价层复核"机制的必要性——forward_extension 作为"弱加分维度"，抽样不稳是已知现象，管线设计已考虑到。

## 7. 评价层复核触发情况（v0.15 §6.1.2 五类）

| 触发条件 | 本次命中数 |
|---|---|
| 1. 总分>70 但中国问题中心性=否 或中国实践解释=否 | 0 |
| 2. 总分<50 但四信号全=是 | 0 |
| 3. 研究创新性>80 但可复核概念或命题=否 | 0 |
| 4. 大量使用标识性概念但 AI 无法定位法学问题 | 0 |
| 5. 预检层 `boundary_review` 触发 | 4（全部） |

**关键发现**：4 篇全部被预检判为 `boundary_review`（两模型一致或多数）。原因多为 PDF 文本的 OCR 乱码、脚注编号残留、案例真实性存疑等**学术规范性疑点**，而非项目口径意义上的"边界"。

这揭示一个真实问题：**预检层当前对 PDF 文本质量的敏感度偏高**，会把"文本工程层"的问题与"项目口径门槛"问题混为一谈。不过这不属于 v0.15 规程本身的缺陷，而是 v2.45 之前就存在的预检 prompt 校准问题，超出本次测试的修复边界（CLAUDE.md 原则：holdout-test 不调 rubric）。

## 8. 第一阶段策略建议

对应 v0.14 测试方案三档判定：

| 档位 | 判定条件 | 本次结果 |
|---|---|---|
| 方案 A（双模型直接可行） | avg_std < 8、高置信度 > 50%、关键分歧 < 20% | avg_std=3.35 ✅、高置信度 50% ⚠️、关键分歧 25% ⚠️ |
| **方案 B（双模型 + GPT-5.5 复核）** | avg_std 8-12 或触发 GPT 复核时能打破僵局、GPT 触发率 < 30% | **GPT 触发率 25% ✅、GPT 在周光权案例上给出独立判断** |
| 方案 C（需强制人工复核） | avg_std > 12 或 GPT 也无法降 std | 不适用 |

**结论**：第一阶段采用 **GLM-5.1 + Qwen3.6-Plus 并发 + GPT-5.5 按 std>8 阈值复核** 的策略具备证据支撑。

### 8.1 后续工作建议（不改 rubric）

1. **预检 prompt 的"文本工程层 vs 项目口径"解耦**：当前 OCR 乱码触发 `boundary_review`，下一版本（v2.46 或 v0.16 规程）应把"文本质量风险"与"项目口径风险"分别输出，避免边界论文被 OCR 问题淹没。
2. **forward_extension 稳定性改善**：该维度在多个样本上持续高波动，可考虑在 v0.16 规程中降低其权重或改为纯定性标签。本次发现不构成立即修复依据，但应累积在下一轮规程迭代 backlog。
3. **validation 集正式泛化验证**：本测试仅覆盖 holdout-test 4 篇。规程冻结后应用 validation 8 篇做一次性泛化验证（不得边跑边改）。

### 8.2 本次不做的事

- 不调 rubric（holdout-test 冻结原则）
- 不扩展样本集（留给 v0.16 规程冻结后的 validation）
- 不切换模型组合（GLM + Qwen + GPT-5.5 决策已定）
- 不做数据库迁移（脚本只写 JSON）
