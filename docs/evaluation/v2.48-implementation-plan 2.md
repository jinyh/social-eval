## 方案选择

考虑到 v2.47 YAML 文件的复杂度（3000+ 行）和时间成本，我们提供三个方案：

### 方案A：完整修改 YAML（最规范，工作量大）

**工作量**: 4-6 小时  
**优点**: 规范、可追溯、可复用  
**缺点**: 需要仔细编辑，风险较高

**具体步骤**：
1. 在前四维的 `ceiling_rules` 中增加 4 个新规则
2. 修改前四维的 `prompt_template`，增加致命缺陷检测步骤
3. 调整 `scoring_criteria`，提高 excellent 档门槛
4. 回归测试 6 篇正负样本

### 方案B：最小化修改 + Prompt 注入（快速验证）

**工作量**: 30 分钟  
**优点**: 快速实施，低风险  
**缺点**: 不够规范，依赖运行时 prompt 工程

**具体步骤**：
1. 保持 v2.47 YAML 不变
2. 在测试脚本中注入额外的评分指引
3. 回归测试 6 篇正负样本
4. 验证效果后再决定是否完整修改 YAML

### 方案C：人工复核 + 规则迭代（最稳妥）

**工作量**: 持续迭代  
**优点**: 最稳妥，可以逐步优化  
**缺点**: 无法自动化，依赖人工

**具体步骤**：
1. 使用 v2.47 进行初步评分
2. 人工复核负样本，记录 AI 误判模式
3. 根据误判模式逐步优化 rubric
4. 迭代 3-5 轮后固化为 v2.48

## 方案B 实施细节

### 步骤1：创建增强版测试脚本

在 `scripts/run_convergence_test_v2.48.py` 中注入额外指引：

```python
# 在调用 AI 评分前，注入额外的评分指引
additional_guidance = """
【v2.48 增强评分指引】

在评分前，请先检查以下致命缺陷：

1. 教科书式梳理（问题创新性）：
   - 论文主要是对既有理论、制度或政策的系统归纳
   - 缺乏问题导向的学术研究
   - 触发条件：全文主要是梳理和归纳，无明确的法学争点
   - 触发后果：问题创新性上限 60 分

2. 理论贴标签（分析框架建构力）：
   - 引用多个理论概念但未与具体问题实质联系
   - 理论只作装饰，未形成分析工具
   - 触发条件：引用理论但未说明如何用于分析本文问题
   - 触发后果：分析框架建构力上限 55 分

3. 逻辑脱节（逻辑严密性）：
   - 段落之间跳跃，缺少衔接
   - 问题与对策脱节（两张皮）
   - 论证链条断裂
   - 触发条件：问题分析与解决方案无法对应，或段落间逻辑断裂
   - 触发后果：逻辑严密性上限 60 分

4. 简单列举（现状洞察度）：
   - 案例与数据简单罗列
   - 未进行深度剖析或实证支撑
   - 触发条件：文献综述或案例分析停留在罗列层面
   - 触发后果：现状洞察度上限 60 分

请在评分时优先检查这些致命缺陷。
"""
```

## 方案A 实施细节（如果选择完整修改）

### 需要修改的文件位置

```yaml
# configs/frameworks/law-v2.48-20260512.yaml

dimensions:
  - key: problem_originality
    ceiling_rules:
      # 现有规则...
      - rule_id: problem_originality.textbook_style_enumeration
        trigger: 教科书式梳理：论文主要是对既有理论、制度或政策的系统归纳，缺乏问题导向的学术研究
        score_ceiling: 60
        priority: 2
        severity: critical
        detection_method: 检查论文是否主要是系统梳理和归纳，而非提出可争辩的法学问题
        examples:
          - 全文主要是对某一制度的历史沿革、现状和域外经验的系统梳理
          - 论文结构为"概念-现状-问题-对策"但缺乏法学层面的争辩点
          - 教科书式的知识归纳，无问题导向
        anti_examples:
          - 虽然包含制度梳理，但明确提出了法学争点并展开论证
          - 系统梳理是为了支撑后续的理论建构或规范分析

  - key: analytical_framework
    ceiling_rules:
      # 现有规则...
      - rule_id: analytical_framework.theory_labeling_without_integration
        trigger: 理论贴标签：引用多个理论概念但未与具体问题实质联系，理论只作装饰
        score_ceiling: 55
        priority: 1
        severity: critical
        detection_method: 检查论文是否引用理论但未说明如何用于分析本文问题；理论只是作为标签或包装
        examples:
          - 引入"工具理性""超级全景监狱"等概念但未与具体问题实质联系
          - 理论概念只在引言或文献综述中出现，正文分析未使用
          - 堆砌多个理论术语但未形成分析框架
        anti_examples:
          - 引入理论并明确说明如何用于分析本文问题
          - 理论概念贯穿全文，形成分析工具

  - key: logical_coherence
    ceiling_rules:
      # 现有规则...
      - rule_id: logical_coherence.argument_disconnection
        trigger: 逻辑脱节：段落跳跃、问题与对策脱节（两张皮）、论证链条断裂
        score_ceiling: 60
        priority: 1
        severity: critical
        detection_method: 检查段落间是否有逻辑衔接；问题分析与解决方案是否对应；论证链条是否完整
        examples:
          - 问题分析部分指出A、B、C三个问题，但解决方案只针对D、E、F
          - 段落之间缺少过渡，读者无法理解为何从A跳到B
          - 论证链条断裂，结论无法从前提推导出来
        anti_examples:
          - 问题与对策一一对应，逻辑清晰
          - 段落间有明确的逻辑衔接词和过渡
          - 论证链条完整，每一步都有支撑

  - key: literature_insight
    ceiling_rules:
      # 现有规则...
      - rule_id: literature_insight.simple_enumeration_without_analysis
        trigger: 简单列举：案例与数据简单罗列，未进行深度剖析或实证支撑
        score_ceiling: 60
        priority: 2
        severity: major
        detection_method: 检查文献综述或案例分析是否停留在罗列层面；是否有深度剖析或实证支撑
        examples:
          - 文献综述只罗列观点，无分析和评价
          - 案例只作为例证，未深度剖析
          - 数据只作为背景，未进行实证分析
        anti_examples:
          - 文献综述有分析和评价，构建研究地图
          - 案例深度剖析，揭示规范冲突或制度问题
          - 数据进行实证分析，支撑论文论点
```
