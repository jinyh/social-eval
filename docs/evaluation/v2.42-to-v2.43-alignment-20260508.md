# v2.42 → v2.43 对齐说明

## 为什么有 v2.43

v2.42(2026-05-07)是 autoresearch 迭代的研究版,针对"分析框架建构力"维度做了 std 优化。
一天后(2026-05-08),评审规程发布 v0.14,**唯一的结构性变化是把评审流程从 3 阶段扩展为 4 阶段**,在六维评分后新增了一个独立的**"自主知识体系信号校验"阶段**。

v2.42 的 YAML 中,这一阶段既没有独立区块,也没有声明输出契约——只在 `review_flags` 和 `expert_review_triggers` 里隐性散落了几条"china-problem"相关触发。

v2.43 就做一件事:**把第 3 阶段在配置层显式建模**,让 YAML 与 v0.14 规程一一对应。

## v2.43 相对 v2.42 的差异

| 范围 | 变化 |
|---|---|
| 六维权重 | 无变化 |
| 基础分公式 `(创新×30+洞察×20+框架×15+逻辑×20)/85` | 无变化 |
| 前瞻加分规则 / 结论可接受性上限 75/65 | 无变化 |
| ceiling_rules / review_flags / expert_review_triggers | 无变化 |
| 六维 prompt 文本 | 无变化(byte-for-byte 一致) |
| std_threshold = 5.0 | 无变化 |
| **新增顶层区块** `autonomous_knowledge_signals` | **本次唯一改动** |
| metadata 字段(version/created/source/changelog) | 更新 |

**评分结果应当与 v2.42 严格一致**——这是本次迭代的红线。若跑 `raw/calibration-regression/` 出现任何分数偏移,视为引入回归,必须回滚。

## 新增区块的作用

`autonomous_knowledge_signals` 顶层区块声明了:

1. **阶段定位**:`stage: 3` + `not_scoring_dimension: true`——不加权、不入基础分
2. **4 类核心信号**:中国问题中心性 / 中国实践解释尝试 / 外部理论转化动作 / 可复核概念或命题(对齐 v0.14 §5.2)
3. **辅助元数据**:是否涉及特殊制度议题、议题类型、是否使用传统文化资源(对齐 v0.14 §7.3)
4. **4 条矛盾触发规则**(对齐 v0.14 §6.1.2):
   - 总分>70 但中国问题中心性=否 → 评价层复核
   - 总分<50 但四信号全=是 → 评价层复核(疑似误判)
   - 研究创新性≥80 但可复核命题=否 → 评价层复核
   - 大量标识性概念但无法定位法学问题 → 评价层复核
5. **输出契约**:required_fields / optional_fields / field_constraints / guardrails(对齐 v0.14 §7.3)

## 重要定位

**v2.43 是"文档性对齐",不是"功能落地"。**

- `src/knowledge/loader.py` 通过 `_normalize_framework_data` 只提取已知字段构造 `Framework`(`loader.py:31-53`),**本区块会落入 `raw_config` 但不被 `orchestrator.py` 消费**。
- 评分管线仍按 v2.42 的三阶段执行(预检 → 六维 → 复核判断),第 3 阶段"信号校验"暂未被调用。
- 这是**有意的设计**:先让配置与规程对齐,冻结字段名;待 orchestrator/precheck/result_validator 真正扩展时,直接以此契约为准,避免返工。
