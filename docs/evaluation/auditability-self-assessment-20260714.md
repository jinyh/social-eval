# 可验证可审计：评价系统的正式效度主张与自审 v1.0

> 版本：v1.0
> 创建日期：2026-07-14
> 性质：设计提案 + 整改基线
> 适用范围：SocialEval 全评价链路（预检 → 六维 → 五轴 → 复核 → 榜单）
> 关联文档：`docs/evaluation/law-ai-assisted-review-rules-v0.16-large-scale-candidate.md`、`docs/evaluation/autonomous-knowledge-system-position-assessment-v0.2.md`、`docs/evaluation/concept-operationalization-v1.0.md`、`results/zhang-wenxian-score-diagnosis-20260714.md`

## 1. 立场

SocialEval 不声称 AI 生成的分数是"对的"。对中国自主知识体系这类评价对象，没有人能合理地声称这一点。

SocialEval 声称的是另一件事：**每一个分数都能被第三方完整还原、复算、质疑；任何一篇论文的入选或落选都能被追溯到原文证据、规则触发、模型分歧记录与专家裁定；最终榜单可由审计链复现。**

这是本项目的正式效度主张。它不是退而求其次，而是对"无真值、高争议、低共识"评价对象唯一能诚实地举起的旗帜。

## 2. 为什么是程序效度而非准确性

对自主知识体系评价，"准确性"是不可达标准：

- **无真值**：自主知识体系是"正在被建构"的对象，没有权威参照系可对。
- **人工判断本身可争辩**：阐释型/思想体系型论文，十个专家的分歧不会比四个模型小——人工评分不是 ground truth。
- **单一分数即黑箱**：任何一个孤立分数都无法被检验。

因此效度主张必须从**分数对不对**转移到**分数能不能被还原、复算、质疑**。这在评价方法学中对应**程序效度（procedural validity）**。对高风险、无真值的评价（学术评奖、课题立项、 accreditation），程序效度即实质效度——不是替代品，而是这类对象唯一站得住的效度形式。

**推论**：评价系统的产品不是分数，是审计链。

## 3. 两个性质：可验证 vs 可审计

明确区分，二者皆需，不混用：

| 性质 | 定义 | 落到本系统 |
|---|---|---|
| **可验证**（verifiable） | 同输入 + 同配置 → 同输出；且输出遵循声明的规则 | 模型调用可复现；CCB/五轴计算遵循 yaml 声明的协议；声明与实现一致 |
| **可审计**（auditable） | 第三方可追溯全链路 provenance 并质疑任一环节 | 输入/输出/时间戳/模型名留痕；每分绑原文证据；模型分歧记录；专家推翻留痕 |

可验证是"实现兑现声明"，可审计是"链路可被外部检查"。前者是底线，后者是产品。

## 4. 自审：已具备的可审计能力

以下能力已在设计中存在，是本系统的真亮点，汇报时应敢讲：

1. **AI 调用全留痕**——输入/输出/时间戳/模型名自动持久化（CLAUDE.md 已列为硬约束），不只存最终结果。
2. **per 维度 per 模型分数 + std**——`results/datasets/three-journals/six-dimension/phase2-r2-v2.55/per-paper/paper-*.json` 的 `dimensions[*]` 含 `round1_scores`、`round2_scores`、`changes`、`raw_outputs`，评分者间信度可见。
3. **R2 交叉评审 changes 记录**——A 组看 B 组、B 组看 A 组后的调整轨迹可追溯，锚定效应（如 DeepSeek 顽固性）可被识别为设计行为而非 bug。
4. **五轴证据等级量尺**——0-1-2 每一分必须对应原文证据或知识树位置（`evidence_quotes` + `rationale`），抑制模型滑回质量判断。
5. **候选节点缓冲区**——五轴产出的 `candidate_nodes` 不直接写入正式 ontology，只进缓冲区待聚类/去重/专家确认，AI 不生成知识树真值。
6. **复核触发器结构化**——围绕"体系归属判断是否可靠"而非分数高低（见 v0.2 §11），低分不被自动当判决。

五轴设计（§4.4–4.6）是"可审计"哲学的更纯粹实现，应立为全系统标杆——其证据等级量尺与候选缓冲机制比六维 0-100 的模型自由度更可审计。

## 5. 自审：五项缺口与验收标准

按可审计性影响排序。这些才是真正该补的——比"权重经验校准""构念效度"务实且可达。

### 缺口 1：契约一致性（声明与实现漂移）

**现象**：`configs/frameworks/law-v2.56.6-20260522.yaml` 声明 `scoring_structure.total_max: 100`，但 `src/reporting/scoring.py` 的 `_core_ceiling_bonus_total` 不做 100 clamp——当核心四维全 100 + 前瞻 bonus 5 + 学术共识度 ≥75（不封顶）时，CCB 实际可达 **105**。审计者读 yaml 会相信满分 100，代码却出 105。这是可验证性的直接破坏。

**验收标准**：
- [ ] `_core_ceiling_bonus_total` 返回前对 subtotal 做 `min(subtotal, 100)`，或在协议层声明 `total_max: 105` 并修改 yaml——二选一，使声明与实现一致。
- [ ] 单测覆盖边界：四维全 100 + FE≥80 + CC≥75 → 期望 100（clamp 方案）或 105（改声明方案）。
- [ ] yaml `total_max` 字段值与代码行为断言一致（加 schema 校验或测试）。

### 缺口 2：权重溯源缺失

**现象**：六维权重 RI 0.3 / PSI 0.2 / TF 0.15 / LC 0.2 / FE 0.05（0.85 归一），五轴五轴等权——无任何决策记录说明来源。审计者问"凭什么 0.3"答不出。权重无真值可校准（本就不可能），但**无溯源**不可接受。

**验收标准**：
- [ ] 在框架 yaml 或单独文件记录每个权重的决策来源（专家共识 / 文献依据 / 历史迭代）、决策日期、决策者。
- [ ] 权重变更进入版本历史，可溯历任调整。
- [ ] 注明"权重为程序性约定，非经验最优"——诚实定位，不冒充数据驱动。

### 缺口 3：操作化定义与生产 prompt 的一致性无校验

**现象**：`concept-operationalization-v1.0.md` 定义了 RI 的"可争辩问题"前置扣分、PSI 的研究地图三要素等规则，但这些规则是否真正体现在 `law-v2.56.6` 的 `prompt_template` 中，无校验。v2.56 曾出现"prompt 仍用旧维度名"的漂移，说明文档规则与 prompt 执行之间存在无声漂移——审计者无法确认"操作化定义是否真的被执行"。

**验收标准**：
- [ ] 建立一致性检查：断言操作化定义的关键扣分规则（前置扣分触发条件、研究地图三要素等）在生产 prompt 中存在。
- [ ] 漂移时 CI 报告，不允许无声偏移。
- [ ] prompt 改动与操作化定义版本绑定（一次 prompt 改动对应一次定义版本号变更）。

### 缺口 4：可复现性契约未声明

**现象**：主力模型 temperature 0.3，非完全确定；seed 是否固定未声明。同输入可能出不同输出，但"可验证"底线要求同输入同输出，或明确声明不确定性量级。当前既未固定，也未声明——审计者无法判断单次分数的波动范围。

**验收标准**：
- [ ] 配置或文档明确声明 temperature、seed 策略。
- [ ] 若不固定 seed，明确声明"单次评分有波动，以多模型中位 + std 为准"——把不确定性写进契约，而非假装确定。
- [ ] std 阈值（High ≤5 / Medium ≤8 / Low ≤12 / Critical >12）作为分数可用性标注，随分数输出。

### 缺口 5：专家复核闭环未持久化

**现象**：专家推翻 AI 分的理由、专家标识、时间是否持久化，决定最终榜能否被复算。若专家裁定只存在于会议纪要而不入数据，则审计链断在人工环节——"可审计"的最后一公里缺失。

**验收标准**：
- [ ] 专家推翻记录字段化：`paper_id` / 原 AI 分 / 专家分 / 理由 / 专家标识 / 时间。
- [ ] 最终榜单可由"AI 分 + 专家覆盖记录"复算，不依赖线下记忆。
- [ ] 专家未推翻的论文，其分数即为 AI 分，同样可溯。

## 6. 对外姿态（专家/领导话术）

向专家：

> 我们不声称 AI 的分数是对的——对中国自主知识体系，没有人能声称这一点。我们声称的是：每一个分数都能被还原到原文证据、规则触发、模型分歧记录，任何一篇的入选或落选都能被复算和质疑，最终由专家在结构化复核里裁定并留痕。AI 的作用是让稀缺的专家注意力能规模化、公平地分配，不是替代判断。

向领导：

> AI 无法可靠评判自主知识体系内容（任何单一评价者都做不到）。我们建的是一套可审计的评价系统：每分有证据、每篇有留痕、争议有复核、候选有规则、专家裁定有记录。这是在高风险学术评价里使用 AI 的唯一可信姿态。

## 7. 整改优先级

| 优先级 | 缺口 | 理由 | 成本 |
|---|---|---|---|
| P0 | 1 契约一致性（105/100） | 直接破坏可验证底线，最便宜 | 低（clamp + 单测） |
| P0 | 5 专家复核闭环 | 审计链最后一公里，缺则全链断在人工 | 中（字段设计 + 持久化） |
| P1 | 3 操作化-prompt 一致性 | 防无声漂移，保障"规则被执行"可证 | 中（一致性检查脚本） |
| P1 | 2 权重溯源 | 审计者首问，必须有答 | 低（记录文件） |
| P2 | 4 可复现性契约 | 影响单次分数波动判断 | 低（声明）/ 高（若要固定 seed + 重跑） |

## 8. 验收清单（整合）

对外可交付的可审计性自检清单：

- [ ] 声明与实现一致（total_max / 协议字段）
- [ ] 权重有决策溯源记录
- [ ] 操作化定义在 prompt 中存在一致性校验
- [ ] 可复现性契约（temperature / seed / 不确定性声明）写入文档
- [ ] 专家推翻记录字段化并持久化
- [ ] AI 调用全留痕（输入/输出/时间戳/模型名）——已具备
- [ ] per 维度 per 模型分数 + std 可见——已具备
- [ ] 五轴每分绑原文证据——已具备
- [ ] 候选节点不直接写 ontology——已具备
- [ ] 最终榜单可由 AI 分 + 专家覆盖记录复算
