# 法学论文 AI 辅助评价规程 v0.17

状态：当前规程  
生效日期：2026-07-16

## 1. 真源与适用范围

本规程规定当前法学论文评价、结果解释和人工复核口径。实现层真源如下：

- 六维 Round 1：`configs/frameworks/law-v2.56.6-20260522.yaml`
- 六维 Round 2：`configs/frameworks/law-six-dimension-r2-v1.yaml`
- 五轴位置评价：`configs/frameworks/law-position-v0.2.yaml`
- 总分协议：`configs/scoring/core-ceiling-bonus-v0.8.yaml`
- 稳定角色：`configs/frameworks/registry.yaml`

历史 Phase 2、交大法学、学术月刊和 E2 结果保持其原始框架身份；其中六维数据主要使用 v2.55。适配层只统一读取结构，不改写历史 JSON，也不把新规程倒灌为历史事实。

## 2. 评价链

当前链路为：预检 → 六维 R1 → 可选六维 R2 → 自主知识信号校验 → CCB 汇总 → 专家复核路由。五轴位置评价独立运行，不与六维或 CCB 加总。

AI 的角色是初筛、分流、证据整理和风险标记，不替代专家审稿、主编判断或真实首创性认定。

## 3. 六维质量评价

六维为研究创新性、现状洞察度、理论建构力、逻辑连贯性、学术共识度和前瞻延展性。各维度按配置中的 prompt、锚点和输出契约独立评分，业务代码不得另设唯一口径。

R2 使用宽松组（GLM-5.1、Qwen3.6-Plus）与严格组（DeepSeek-V4-Pro、Kimi-K2.6）交叉复核。每个模型只参考对方组的 R1 意见；接受或拒绝对方观点均须给出可复核理由。启用 R2 时两组都必须至少有一个模型，未分组模型不得静默加入。

API 默认不启用 R2，以控制成本；单篇和批量上传可显式设置 `cross_review_enabled=true`。启用后，R1/R2 评分、原始结构化响应、调用日志和可靠性结果分别持久化，并以 `final_round=2` 作为报告主视图。

## 4. CCB 总分

唯一当前总分为：`min(core_base + forward_bonus, consensus_ceiling, 100)`。

- `core_base`：研究创新性 0.30、现状洞察度 0.20、理论建构力 0.15、逻辑连贯性 0.20，按权重和 0.85 归一化。
- `consensus_ceiling`：学术共识度低于 60 时封顶 65；60–74 时封顶 75；不低于 75 时不另设封顶。
- `forward_bonus`：满足逻辑连贯性、学术共识度和核心四维前提后，按前瞻延展性最多加 5 分。

历史字段 `overall.round2_final_score_mean` 是六维简单均值，只作为历史诊断字段；报告和排名主分必须标为 `ccb_score`。

## 5. 五轴位置评价

五轴为对象归属度、材料归属度、范畴自主度、解释目标归属度、体系映射度，每轴 0–2，总分 0–10。它回答知识单元在中国法学自主知识体系中的位置归属，不回答论文质量高低。

五轴 R2 的 skip/light/full 触发、模型、证据和保守聚合规则以五轴配置为准。逐篇历史结果未写 framework 字段时，以同目录 manifest 登记的框架为权威来源。

## 6. 可靠性与专家复核

可靠性分级：high（std≤5）、medium（5<std≤8）、low（8<std≤12）、critical（std>12）。六维 R2 后任一维度 `std>8` 时，必须标记专家复核；当前生产策略不自动调用 GPT 仲裁，也不通过继续增加同模型轮次强行压低真实学术分歧。

预检边界、证据不足、信号与六维矛盾、内容审查降级和结构化输出不完整，同样可以触发专家复核。系统必须保存触发原因，不得只保存最终分。

## 7. E2 候选池

E2 的硬条件为五轴总分不低于 9 且 E1 CCB 不低于 80。Top80、学科保底和年度保底的所有补入均必须继续满足两项硬条件；候选不足时接受保底缺口，不得从宽池绕过门槛。

E2 重排名把 E1 与 E2 的同维四模型分数合并为 8 个值，使用 median(8) 池化，再按 CCB 计算总分。E2 原始结果保留 R1/R2；出池历史结果不删除，只退出当前 pool/ranking。

## 8. 审计与历史兼容

Paper ID 必须来自各数据集权威元数据，不得由文件顺序或中间缓存重建。路径失效时只允许以 dataset + Paper ID 回退查找，适配结果必须同时暴露原存储路径与解析路径。

历史原始响应确实未保存的槽位标记为 unavailable，不以重新调用模型伪造历史响应。完整性审计必须同时检查预期论文 ID、预期维度、模型评分槽位、manifest、摘要和排名，整篇文件或整个维度缺失均为结构错误并阻止应用修复结果。
