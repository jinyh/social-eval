## 核心判断

SocialEval 当前定位是"编辑辅助预审"——论文进来，评价出去。但系统真正的资产是**对人文社科学术文本的结构化理解和多视角判断能力**。这个能力至少可以向三个方向延伸：

1. **知识生产基础设施**：从评价终稿到辅助知识生产全过程
2. **教学创新系统**：让文科创新过程可见、可反馈、可训练
3. **学术生态智能**：为编辑部、学科和政策层提供元研究能力

三者不是互斥的产品线，而是同一能力的不同应用面。任何方向若要推进，都需回到需求层确认定位边界。

## 第一部分：从评价到知识生产基础设施

### 1.1 生成式写作脚手架

把评价维度反转为写作指导。六维框架本身就是学术写作隐性规范的显性化——不必等论文写完再评判，可以在写作过程中按维度给出结构性提示。

应用场景：

- 博士生提交论文草稿，系统不给终审意见，而是指出"你的论证深度集中在描述层，尚未进入因果解释层"
- 差距诊断："距离本刊近三年同主题录用稿的平均水平，你在方法创新性上处于 X 位置，具体表现为……"
- 这是 formative feedback，不是 summative evaluation

### 1.2 学术概念演化的计算图谱

"中国自主知识体系"最核心的问题：哪些概念是中国学者原创的，哪些是对西方框架的翻译/嫁接，哪些正在分化出本土独立语义？

SocialEval 已经处理了大量法学稿件的全文。如果把评价引擎的文本理解能力转向概念追踪：

- 从数百篇稿件中提取核心概念及其定义方式
- 追踪同一术语在不同作者/不同年份中的语义漂移
- 自动识别"真正的理论创新"（原创概念 + 独立论证结构）vs."翻译 + 本土案例填充"
- 生成领域概念图谱：哪些概念已经稳定、哪些正在争议、哪些还是空白

这比单篇评价的学术价值大一个数量级。

### 1.3 辩证综合引擎

当前系统给每篇论文独立评价。但学术知识推进的真正机制是对话和争鸣。

当系统积累了同一主题的多篇稿件后，可以自动生成研究前沿地图：

- "当前本领域存在三个对立立场，分别由 A、B、C 群体持有"
- "核心分歧在于 X"
- "尚无论文尝试 Y 路径的综合"

对编辑来说这是组稿策略；对学者来说这是选题指南。

### 1.4 跨学科方法论比较

同一个社会现象（如"平台治理"），法学怎么研究、社会学怎么研究、计算机怎么研究？系统可以自动识别不同学科的分析框架差异，辅助做真正的交叉研究而非简单拼贴。

围绕"共同富裕""新质生产力"这类议题，从多学科投稿中自动抽取各学科的独特贡献，帮助政策研究者看到学科壁垒之间的盲区。

## 第二部分：文科创新过程的 Artifact 化

### 2.1 问题诊断——文科创新的"暗物质"

理工科的创新过程天然产出 artifact：代码、实验记录、数据集、原型。这些中间产物可追溯、可评价、可复用。

文科的创新过程几乎全部发生在脑子里：

- 怎么从一个模糊直觉走到一个清晰的问题意识？
- 为什么选了这个理论框架而不是那个？
- 读了 50 篇文献，真正改变你思路的是哪 3 篇，怎么改变的？
- 论证结构经历了几次推倒重来？
- 哪些反驳你认真考虑过又放弃了？

最终提交的论文把这些全部抹平了——呈现一个光滑的、仿佛一气呵成的成品。导师看到的是结果，学生经历的过程是黑箱。

**没有 artifact，就没有 feedback loop。这是文科教育效率低的根本原因。**

### 2.2 文科创新 Pipeline：五阶段 Artifact 体系

#### Stage 1：问题感知 → 问题演化日志

不是直接写"研究问题"，而是记录：

- 初始困惑是什么（一个现象、一个矛盾、一个案例）
- 经过哪些阅读/观察，问题变形了几次
- 最终研究问题与初始直觉的差距有多大

**AI 角色**：不是帮学生"想出好问题"，而是逼学生把模糊直觉外化成文字，然后追问——"你说的'不公平'具体指什么？是程序的还是结果的？跟现有文献的定义一样吗？"

#### Stage 2：概念建构 → 概念定位图

文科创新的核心是概念。一个真正的贡献往往是：提出一个新概念，或者重新定义一个旧概念的边界。

Artifact 内容：

- 我的核心概念是什么？
- 它跟相邻概念的边界在哪里？（画区分）
- 它跟上位/下位概念的关系？（画层次）
- 现有文献对这个概念的定义有哪些版本？我为什么不满意？
- 我的定义跟 A 的有什么不同，跟 B 的又有什么不同？

**AI 角色**：帮助生成概念对比矩阵，追问定义的模糊地带，指出"你的定义跟 X 2019 年的说法实质等价，你确认你在做新贡献吗？"

#### Stage 3：文献对话 → 论辩地图

不是传统的文献综述（A 说了什么、B 说了什么），而是：

- 我要加入的对话是什么？对话中已经有几种立场？
- 每种立场的最强论证是什么？
- 它们各自的盲点是什么？
- 我的位置在哪里——是补充、修正、综合还是颠覆？

**AI 角色**：当学生只读了 A 学派的文献时，主动引入 B 学派的核心反驳；当学生声称"现有研究未关注 X"时，检查是否真的没有。

#### Stage 4：论证建构 → 论证骨架 + 反驳清单

- 主论点 → 支撑理由 → 证据/案例
- 每个理由的替代解释是什么？
- 最强的可能反驳是什么？我怎么回应？
- 论证中最薄弱的一环在哪里？

**AI 角色**：扮演尖锐的审稿人。不是等论文写完再评价，而是在骨架阶段就发起攻击——"你的因果推断依赖 X 假设，如果 X 不成立呢？""你用了 3 个案例但它们都是同一类型，这算不算选择性举证？"

#### Stage 5：写作与修订 → 版本差异 + 修订理由

类似代码的 git diff，但对象是论证结构：

- 第 2 稿相对第 1 稿，核心论点变了还是没变？
- 如果变了——是因为发现了新证据，还是因为逻辑走不通？
- 如果没变——证据和论证结构怎么加强的？

### 2.3 对教学双方的意义

#### 导师端

传统模式：学生写完一稿 → 导师花 2 小时读 → 给模糊反馈（"论证不够深入""文献还要补"）→ 等下一稿。

Artifact 模式：

- 导师看到问题演化日志，能精确定位"你在第 3 步走偏了"
- 导师看到论辩地图，发现学生完全没考虑某个学派
- 导师看到反驳清单，发现学生回避了最核心的质疑
- 反馈从"你的论文有问题"变成"你的思维过程在这一步出了问题"

一个导师一学期看 50 篇终稿很痛苦，但看 50 份 1 页的"论辩地图"并给反馈，效率完全不同。

#### 学生端

- 不再是"凭感觉写完再被毙"的赌博循环
- 每个阶段有明确的质量标准和 AI 反馈
- 创新过程从不可言说的天赋，变成可训练的结构化技能
- 学生之间可以比较 artifact，互相学习彼此的思维路径——这在只看终稿的情况下不可能

#### 评价端（回接 SocialEval）

- 对比 artifact 路径和最终成品的关系：哪些过程特征预测高质量产出？
- 发现"看起来好但过程空洞"的论文（可能是 AI 代写的信号）
- 发现"看起来一般但过程扎实"的论文（可能是有潜力但写作能力暂时不够的学生）

### 2.4 对"中国自主知识体系"的特殊意义

1. **让"原创"可操作化**：当学生必须在概念定位图中明确标注"我的概念跟西方文献 X 的区别是什么"，原创性就从考核终稿时的主观印象，变成过程中的显式要求。

2. **破解"洋八股"**：很多中国文科学生的训练模式是"选一个西方理论 → 找中国案例套上去"。如果论辩地图要求你明确标注"我是在检验这个理论、修正这个理论、还是用中国经验提出替代理论？"——无意识的套用就被显式化了，可以被挑战。

3. **跨代际知识积累**：现在一个导师退休，他的指导方法就消失了。如果 artifact 积累下来，后来的导师可以看到"这个方向的学生在 Stage 2 普遍遇到什么困难"，教学知识本身也成了可传承的制品。

## 第三部分：学术生态智能

### 3.1 编辑部的战略大脑

期刊编辑部最缺的不是审稿效率，而是学术判断的系统性。

- **稿源结构分析**：这一年收到的稿件，方法类 vs. 规范类 vs. 实证类的比例是什么？跟领域发展趋势匹配吗？
- **审稿人-稿件匹配**：基于对审稿人已发表论文的理解，智能推荐最有能力评判特定创新点的审稿人——而不只是"研究方向一致"。
- **期刊定位漂移预警**：对比录用稿件的维度分布变化，自动发现"本刊在方法创新维度的平均分逐年下降，是否正在丧失方法创新引领力？"

### 3.2 "自主知识体系"的实证诊断

用系统来实证地回答"中国自主知识体系建设到什么程度了"这个问题本身。

- 定义操作化指标：概念原创率、论证结构独立度、引用网络中本土文献的核心度
- 在大规模稿件上跑这些指标的时序变化
- 产出的不是论文评价，而是学术生态的诊断报告

用数据说话——"自主知识体系"到底是一个口号还是正在发生的事实。

### 3.3 研究价值（系统本身作为研究对象）

- **评审一致性研究**：多模型交叉评审的 std 分布，是研究 AI 评审可靠性的素材
- **AI 评审偏差研究**：某类论文是否被系统性低估
- **跨学科评审标准比较**：若扩展到多学科，维度权重的学科差异是学术评价研究课题
- **过程 artifact 与产出质量的相关性研究**：哪些思维过程特征预测高质量学术产出

## 第四部分：架构可行性

### 4.1 现有能力到延伸方向的映射

| 现有能力 | 延伸为 |
|---------|--------|
| 六维评价 Prompt 框架 | 每个 Stage 的 artifact 评价/反馈 Prompt |
| 多模型交叉验证 | 多视角反驳生成（一个模型扮演 A 学派，一个扮演 B 学派） |
| `src/knowledge/` 知识体系加载 | 学科概念图谱、论辩结构模板 |
| 编辑工作流（投稿→预审→复核） | 教学工作流（提交 artifact→AI 反馈→导师确认→下一阶段） |
| 专家复核机制 | 导师对 AI 反馈的 override 和补充 |
| 结果不可变快照 | 学生思维过程的版本化存档 |
| `configs/frameworks/*.yaml` 维度配置 | Artifact 质量评价维度配置 |
| 摄取管道（PDF/DOCX/TXT） | 结构化 artifact 输入（Markdown/JSON） |

### 4.2 关键架构差异

评价系统的用户是**编辑**，教学系统的用户是**学生和导师的配对关系**。交互模式完全不同：

- 不是"提交→等结果"，而是持续的对话式推进
- 不是一次性终审，而是多阶段 gate-keeping
- AI 反馈需要导师可 override——最终学术判断权在人
- 版本管理的粒度从"论文稿"变成"单个 artifact"

### 4.3 不需要重建的部分

- `configs/frameworks/` 的 YAML 配置已经解耦了评价逻辑和代码——换成 artifact 反馈 Prompt，引擎层不需要重写
- 多模型交叉机制天然适合"多视角判断"类任务
- 数据库模型的期刊/投稿层级可以平行扩展为课程/作业层级
- 权限与角色体系（投稿人/编辑/专家）可以映射为学生/导师/外审

## 第五部分：风险与约束

| 风险 | 说明与缓解思路 |
|------|---------------|
| 刷分污染 | 学生针对维度优化而非真提升。缓解：诊断式反馈而非预测分式；artifact 过程不可伪造。 |
| 数据红线 | `raw/label/` 真实审稿意见等敏感数据不能直接做教学样本。缓解：脱敏或合成样本。 |
| 定位漂移 | 从"编辑初筛工具"变成"教学产品"，改变项目性质。缓解：明确模块边界，需求层确认。 |
| 学科适用性 | 六维五轴针对法学期刊投稿，直接套用到其他场景有偏差。缓解：新场景先校准维度。 |
| 依赖性 | 学生过度依赖 AI 反馈，弱化自主学术判断。缓解：AI 只做追问和挑战，不做结论。 |
| 创新窄化 | AI 的反馈可能把学生导向"安全"路径。缓解：多视角模型设计，鼓励而非惩罚冒险。 |

## 第六部分：参考思路与下一步

### 参考思路

- 郭毅可（香港科技大学）：AI 作为研究伙伴而非工具、研究过程可见化、计算思维对人文学科的意义
- Process-oriented pedagogy：从评价 product 转向评价 process
- Epistemic apprenticeship：学术训练作为认知学徒制，AI 降低师徒比的瓶颈
- Concept-driven innovation：文科创新的核心单元是概念，而非数据或方法

### 可能的下一步动作

3. 与法学院合作导师讨论 artifact 体系是否匹配真实教学痛点
4. 评估 SocialEval 现有 Prompt 框架向 artifact 反馈 Prompt 迁移的技术成本
